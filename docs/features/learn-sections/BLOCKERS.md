## Decisions taken alone

- **Lane layout.** Four lanes in their own worktrees (`C:/s/sec-core`, `C:/s/sec-browser`, `C:/s/sec-tools`, `C:/s/sec-evidence`) on branches `rehearsal/sections-<lane>`, merged into `rehearsal/sections` in the order CORE, BROWSER, TOOLS. Main's CLAUDE.md asks for isolated worktrees per lane. What is needed: nothing.
- **TOOLS: the example code check reads the request's `context`.** `learn-section-make/code.js` (C §2b) puts the source's top-level Python module names on one `context` line (`Source modules, never imported: a, b`, `learn-primitives.js SOURCE_MODULES_LINE`) of the `slash` perform; the section variant of `code_sample` (madeBy `learn-section`) refuses an answer that imports one of them or does a relative import, and an answer with an output claim (`>>>`, `# output`, `# ->`). Typed /code is unchanged (60 lines, 2000 characters, no new checks). Done instead of a new artifact-body field, which CONTRACT.md does not have. What is needed: BROWSER's `learn-slash.js` sends `perform.context` as the artifact body's `context` (CONTRACT already says so).
- **TOOLS: `ctx.record` for data plots (C §9).** `graph.js` traces a `data_plot` value to `ctx.record` (the rehearsal record's measured numbers: metrics, step times), the anchored lines and this section's notebook files in `ctx.earlier`. CONTRACT.md's ctx has no `record`; without it a `data_plot` that claims measured values is corrected to `illustrative: true` and the correction recorded. What is needed: CORE puts the rehearsal record (any JSON; its numbers are read) on `ctx.record`, or the integrator adds it to CONTRACT.md. C §9c.3 (a graph on a structure beat) is compose's fit check: not built here.
- **TOOLS: `notebook-runtime.js` not in the TOOLS tree yet.** `learn-section-make/notebook.js` imports `unavailableImports` from `packages/web/src/notebook-runtime.js` (BROWSER, CONTRACT.md) with a dynamic `import()` inside `validate`, so the module loads without it and the unit tests inject the list (`validate(input, ctx, { unavailableImports })`). What is needed: the file on the integrated branch (merge BROWSER before TOOLS, as planned); until then a real notebook Make fails at that import. Workspace helper modules (`helpers[]` .py files) are never marked unavailable.
- **TOOLS: notebook lineage across sections.** A `buildup` notebook names the sections it continues (`continues`), recorded as `notebookLineage` with this section's id; the helpers it imports must be defined in the `.py` files it carries. CONTRACT.md's ctx has no earlier sections' notebook files, so a copied helper is not compared with the original. What is needed: `ctx.notebooks` (earlier sections' notebook files) if the integrator wants that check.
- **TOOLS: server-side page text for arXiv papers (S) uses pdf.js in the Worker.** `arxiv.js readArxivPaper(id, fetcher, { pages: true })` fetches the PDF (the existing 12 MB cap) and returns `pageCount` and `pages: [{ page, text }]` (first 100 pages) through `pdfPageTexts`, pdf.js's legacy build loaded by dynamic `import()` with its worker in the same thread (`globalThis.pdfjsWorker`). Verified in Node on the generated `long-pdf-fixture.mjs` PDF; not run in workerd. Costs: an esbuild bundle of the two pdf.js files measured 3.77 MB unminified, added to every Worker bundle that imports `arxiv.js` (the control plane and the app Worker); `pdfjs-dist` is a `packages/web` dependency resolved from the root `node_modules`, not declared in `packages/control-plane/package.json` (package files are not TOOLS'). A PDF that cannot be read returns `pages: null` with `pagesError`, never an error; `learn-section-make/arxiv.js` then accepts the quote and records `quoteCheck: 'unchecked'` (the browser records `not_found` on open, S). Ordinary callers (no third argument) are unchanged. What is needed: CORE's wrapper calls `readArxivPaper(id, undefined, { pages: true })` for `read_arxiv_paper` and stores the result as `ctx.turn.papers[id]`; the integrator builds the Worker once to confirm the size and that pdf.js runs in workerd, or decides to move it behind a service.
- **TOOLS: a quote still not on its page after the re-ask.** C §6d says the card then opens with no highlight and `highlight: 'not_found'`; the validator only returns the re-ask error, and the dispatcher's second failure skips the item. What is needed: CORE, if it wants 6d's fallback, makes the card from the second answer with the quotes dropped (ctx has no attempt number).
- **TOOLS: `papers[]` in the catalogue (U).** `catalogue.py papers_of(files)` finds arXiv references by regex in READMEs, `CITATION*` and Python files (docstrings and comments), first citation wins, at most 20, as `[{ id, title, source: 'path:line' }]` (title = the Markdown link text, else empty). Set on a fresh catalogue and on a stored one that is sent back for `learn`; `schemas/catalogue.json` gains the optional `papers` property (the document is `additionalProperties: false`, so the schema change is part of U). A stored catalogue that already has `learn` is never sent back, so it has no `papers` until the repository is re-indexed. `jsonschema` is not installed on this machine: the checks ran with `uv run --no-project --with jsonschema --with pytest` (the four `test_catalogue_*.py` files, 66 passed, and the in-file `python catalogue.py --self-check`). What is needed: CORE reads `catalogue.papers` into the paper item's prompt (ctx has no catalogue field; the arXiv validator requires the paper to be read this turn either way).
