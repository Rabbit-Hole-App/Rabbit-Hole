# Codebase index: layers stored once, a tool for the Tutor, Learn decoupled from Run (owner 2026-11-19 09:07–09:20; Reviewer, read on learn/section-run-fixes 3a8c26e8)

Owner's decisions: the Tutor indexes the code first at a high level and asks what the learner wants; deeper layers on demand; the index is a tool the Tutor can call at any time; stored once, never rebuilt for nothing; the README is one signal, and how well it matches the code is an output; no vector DB yet; shared snapshots are a priority fix; Learn must not fail when the Run catalogue fails.

## 0. What exists (read)
- **Snapshot.** `packages/lesson-renderer/index_repository.py` on the Fly worker: Graphify static extraction, no model. Output `{ version, repo, commit, files: { path: text }, skipped, graph: { nodes, edges } }`. Caps: 20 MB archive, 32 MB expanded, 2,000 files, 512 KB a file, 8 MB text, 10,000 nodes / 30,000 edges; over a cap the import fails.
- **Storage.** R2 `REPOSITORY_SNAPSHOTS`, key `learn-repositories-dev/<appId>/<commit>/graphify-0.9.63.json` (`repositories.js:202`); D1 `repository_versions(app_id, commit_sha, storage_key)`, primary key per **app** (`repository-schema.sql:6`). The import object looks for a cached row by app and commit only (`RepositoryImports.fetch`), so the same repository and commit connected by two people is indexed twice.
- **Re-index.** `POST /api/repositories/:id/refresh` → `enqueue` → branch head; a commit already in `repository_versions` for that app is ready at once.
- **Tools** (`repository-context.js repositoryTool`, verified): `get_repo_overview` (first 100 file paths, top 18 symbols by degree, skipped files), `search_code` (the whole query as one substring per line, first 25 lines; up to 20 nodes whose label or path holds any term), `query_graph` (label and path term scoring, 8 seeds, one hop, 40 edges), `explain_symbol`, `get_relationships` (35 edges), `find_connection_path` (8 hops), `read_source` (at most 120 lines). All synchronous over the snapshot; used by twelve modules (chat, plan, brief research, make, code-explain).
- **Learn topics.** Built inside the Run catalogue: `catalogue.py add_learn` on the Fly controller, started at every import (`triggerCatalogue`), stored as `catalogue-cpu.json` under the app's prefix (`learn-rehearsal.js:38`). When the catalogue fails or is empty the browser shows `SENTENCES.catalogueFailed` and Learn has nothing (the owner's datasette canvas, 11-19).
- **Start of the flow.** `TutorRehearsal.jsx:93` asks `GET /api/learn/codebase` once when the canvas opens; `canvasRepository` returns a repository only once it is indexed, so a fresh import never starts the Tutor. Nothing opens the right panel.
- **Models.** Tutor calls: the `LEARN_TASKS` model (Sonnet 5.5) through `sectionTurn` (`learn-section-research.js:98`: research tools + one submit tool, repairs, spend cap). Router and judge: JEV (`learn-grade-jev.js askJev`). Embeddings code exists for video moments (`learn-moment-index.js`: Workers AI `@cf/baai/bge-m3`, Vectorize `MOMENTS`); no binding for it is in the repository's wrangler configs. **Claude Code: say where `MOMENTS` and `AI` are bound and whether they are live in production.** Not used by this spec.

## 1. Shared snapshots (priority)
- New table (migration): `repository_snapshots(repo TEXT, commit_sha TEXT, version TEXT, storage_key TEXT, created_at, PRIMARY KEY(repo, commit_sha, version))`.
- New key: `repositories/<owner>/<repo>/<commit>/snapshot-<VERSION>.json`.
- `RepositoryImports.fetch`, after the visibility check that `enqueue` already makes: look up `repository_snapshots` by repository, commit and indexer `VERSION`. Hit → `INSERT OR IGNORE repository_versions(app, commit, that key)`, mark the app ready, no indexer call. Miss → index as today, write to the new key, insert both rows.
- `repositorySnapshot()` is unchanged (it reads `storage_key`); old rows and old keys keep working. Only public repositories are imported, so one snapshot serves everyone.
- Test: two apps, same repository and commit → one indexer request, two `repository_versions` rows, one object.

## 2. The index: layers, stored once per repository and commit
New module `packages/control-plane/src/learn-index.js`, run in the Worker like `learn_plan` (no Fly controller).
- **Store.** R2 `repositories/<owner>/<repo>/<commit>/index/<layer>[-<scope>].json`; D1 `repository_index(repo, commit_sha, layer, scope, storage_key, status, usd, created_at, PRIMARY KEY(repo, commit_sha, layer, scope))`, status `building | ready | failed`. `indexGet(env, repo, layer, scope, { build })`: ready → the stored JSON, no model call; missing and `build` → build, store, return; `building` younger than 2 minutes → `{ status: 'building' }` (the caller polls). Whoever builds first pays (metered as today); everyone after reads it free.
- **Layer `overview`** (the first thing built for any repository). Deterministic digest from the snapshot, then one `sectionTurn` (task `learn-index`, research = `read_source`, `search_code`, `query_graph`, at most 8 steps, cap US$0.15):
  - digest: file counts and paths by role (`fileRole`, `learn-codebase-goals.js:85`), top-level folders; manifests in full up to 6 KB (`pyproject.toml`, `setup.py`, `setup.cfg`, `package.json`, `Cargo.toml`, `go.mod`, `requirements*.txt`); the 40 symbols with the highest degree and their paths; entry points (manifest scripts, `if __name__ == '__main__'`); test file names and test names from the graph; the first 15 lines of the 20 most-connected source files; README text up to 6 KB, labelled "README (a claim about the code, may be out of date)".
  - submit `{ summary (1–2 plain sentences: what this code does), options: [{ id, label (≤ 6 plain words), what (one sentence), anchors (1–4 paths in the snapshot, at least one source file), kind }] (1–6), cannot: [{ thing, why }] }`. Same field names as today's `doc.learn`, so `learnOf({ learn: overview })`, the opening, `learn_intro` and `learn_plan` read it unchanged.
  - validate: anchors exist; labels and sentences pass the one rule (no path, file name or flag); nothing about whether the code can run. It fails only when the model is unavailable or over the cap.
  - prompt rule: "Decide from the code: manifests, symbols, tests and the files you read. Use the README only where the code agrees with it."
- **Layer `topic`**, scope = option id or a slug of what the learner typed. Built when a topic is chosen. One `sectionTurn` (research as above plus `get_relationships`, 10 steps, cap US$0.10) starting from the option's anchors and following imports and callers. Submit `{ found, files: [{ path, why }] (≤ 12), symbols: [{ label, path, line, why }] (≤ 20), flow: [{ what, anchors }] (≤ 8, in the order the code runs or is best read), needs: [plain words the learner should know first], near: [option ids] }`. A typed topic the code does not contain → `found: false` with `near`, and the Tutor says so with those rows. `learn_intro`, `learn_plan` and the section brief receive it as `INDEX` text and may anchor to any file it lists, not only the option's 1–4 anchors.
- **Layer `readme`** (built in the background after `overview` with `ctx.waitUntil`, and on demand). Step 1, one model call: at most 10 checkable claims from the README, each with the code lines that bear on it (`read_source` ranges) or none. Step 2, JEV judges each claim against its lines as a Choice question (`matches` / `contradicts` / `not shown`), the call shape of `chat-capability-route.js`. Stored `{ present, claims: [{ claim, verdict, evidence: [{ path, start, end }], note }], score: matches / claims }`; JEV unavailable → the model's own verdict with `judged: false`. Shown nowhere yet; the Runbook's corrected README is a later slice that reads this.
- **More layers later** (a file, a symbol): same store, `layer: 'file'`, `scope: path`. Not built now.

## 3. The index as a tool
`codebase_index` `{ layer: 'overview' | 'topic' | 'readme', topic? }` → `indexGet(..., { build: true })` within the caller's spend cap. Async (it needs `env`), so it is registered beside the repository tools in the two loops that have `env`: `learn-section-research.js DEFS` and the chat's tool loop for a canvas with a repository. Description: "What this codebase offers (overview), what a topic involves and where (topic), or how far the README matches the code (readme). Stored; a repeat call costs nothing."
Small fix while there: `search_code` also matches per term (lines holding the most query terms first) when the whole phrase matches nothing.

## 4. Learn no longer waits for the Run catalogue
- Browser (`TutorRehearsal.jsx`): poll `GET /api/learn/codebase` until `repository` is set (the "Reading <name>" shimmer), then `POST { action: 'learn_index', layer: 'overview' }` ("Working out what <name> offers"), then `sourceArrived({ kind: 'repository', summary, options, cannot })` → `learn_open` → the opening. When the canvas opens on a newly connected repository the right panel opens on Chat (connect only, never on a later visit).
- Choosing a topic: `learn_index` layer `topic` runs first (shimmer "Reading the code for it"), then `learn_intro`, depth, plan as today.
- `triggerCatalogue` and every catalogue read run only when the server flag `RUN_IT=true` (off in every config); the browser's `runIt` flag follows it. `catalogue.py add_learn` stays for that path and is no longer what Learn reads.
- `catalogueFailed` is not shown on the Learn path. Index failure sentence: "I couldn't read **<name>** well enough to say what it offers. Try again." with the Retry row.
- For the record: read why datasette's catalogue failed on canvas-9c9a18cc (job log, `catalogue.error`) and report it; the fix above does not depend on the answer.

## 5. When the code changes
- Refresh as today gives a new commit and a new snapshot (shared, §1). At snapshot write, also store `files.json` beside it: `{ path: sha256 }`.
- Index for the new commit: `overview` is rebuilt (one call) with the previous overview given as context ("keep an option's id where the topic still exists"); a `topic` or `readme` entry whose listed files and evidence files all have the same hashes is copied to the new commit (`carriedFrom`), anything else is rebuilt on its next use.
- A canvas's accepted plan stays on the commit it was made from (as today).
