# Scene composition scorecard

**Approved rubric, owner 2026-11-14 12:05 PT.** Record card, depth, revision, reviewer, date and evidence. Apply the same ten checks to reference templates and model-composed scenes. Initial application: [the nine stepper cards](references/stepper-composition-review.md).

| # | Yes/no check | Evidence for Yes |
|---|---|---|
| 1 | Does the drawing show the mechanism that answers one clear question? | Identify the observation and the marks that demonstrate it. |
| 2 | Does the card hold at the aha until the learner acts? | Inspect the decisive state; timed scenes pause there. |
| 3 | Does each parameter change relevant evidence or the experiment? | Compare actual inputs and outcomes; justify a fixed comparison if there is no parameter. |
| 4 | Is every explanatory part bound to declared data, state and words? | Trace highlights, arrows, ghosts, callouts and readouts to their sources. |
| 5 | Does the complete card fit with a native 640 px scene? | Render initial, aha, boundary and longest-label cases; record viewport and captures. |
| 6 | Do story, labels and controls name the same objects and events? | Compare the narrative with every changing part. |
| 7 | Does depth add mechanism without clutter? | Overview: one changing region, one row for grids; Standard: comparison; Deep: formula or count. Deep mitosis is the density ceiling. |
| 8 | Are values computed correctly and placed once? | Independent checks at defaults/bounds; callouts locate, readouts quantify. |
| 9 | Are marks, words and controls legible within the declared budget? | Inspect rendered contrast, labels, ghosts and control layout; count parameters separately from navigation. |
| 10 | Do Reset, boundaries and keyboard interaction preserve predictable state? | Exercise defaults, keys, focus and named disabled controls; steppers have no fake clock. |

Answer **Yes** or **No** after inspection. Use **Unknown** for missing evidence and **Not yet reviewed** before assessment; neither is a pass. Source dimensions and Node adapters cannot prove rendered fit, legibility or keyboard behavior.

All ten Yes answers are required for a rubric pass; a No requires revision. This is a review rubric, not a new production gate. The existing shadow judge remains nonblocking. Runtime parts and composition support are proposed, not implemented by this document.
