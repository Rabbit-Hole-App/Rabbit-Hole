# /explain and /interactive test ledger

Every test run for the written `/explain` (and `/interactive`) work, with its result, the fix it led to and whether that fix is approved for production. Owner rule (2026-11-08): no test without a fix decision; report every test in this table.

Columns: **Pass/Fail** is the test's own verdict against its goal. **Prod** says whether the fix it led to is approved for and/or live in production: LIVE (in a released build), APPROVED (owner approved, not released yet), NOT YET (built or proposed, not approved or not released), n/a.

## Release gate tiers (owner decision, 2026-11-09, from release 119)

Every gate row from release 119 on starts its **Test** cell with its tier, `[tier 1 smoke]` or `[tier 2 full 3x]`, and its Result names the gate verdict (`node scripts/explain-bench/gate-check.mjs <report dir> <SHA>` prints `GATE: PASS|FAIL <SHA> tier=smoke|full`). Rows below predate the rule.

- **Tier 1, smoke** (every release candidate): one run of the fixed set `smoke` (`scripts/explain-bench/sets/smoke.json`, versioned, built by `build-smoke-set.mjs`; target at most 15 minutes and US$1.50): every diagram kind at least once, the fragile groups (matrix/heatmap, formula plots, sequences with self-messages, two-structure prompts), the picture-routing sample and the 13 Lesson 04 demo prompts. The gate is `gate-check.mjs --tier smoke --baseline <judged run dir>` (owner 2026-11-10; one pass is too small for the full tier's absolute rates): delivery, the two picture lines (needed 100%, none belongs 0) and right kind on verified prompts (at least 80%) are hard absolute limits; every other line (factual error, repairs, p90, noun-box, faithfulness not and fully, claims beyond the prose) is compared with the baseline's mean on the same prompts, the baseline being the last passing release's judged 3x run, and fails only if worse by more than the tolerance (the larger of 3 items or 5 percentage points, 4 items for factual error; p90 +2000 ms; calibrated on the 118 run's own pass-to-pass spread; `SMOKE_TOLERANCE` in gate-check.mjs). Smoke prompts the baseline does not cover are reported as no baseline and not failed. Deterministic server changes (Q0 coercion, cap and strip-type guards, renderer ticks) ship on a green smoke tier alone.
- **Tier 2, full** (3x of the six core sets, today's thirteen lines with the spread column): required when a change touches the author system prompt or the schema bundles, the model, profile or temperature, the planner (the JEV decision model, the steer rules), the selector library-wide (Codex's keyword audit, Q5), or the formula sampler (Q2). Q1 and Q2 are tier 2. The 42-prompt baseline set runs in tier 2 only.
- **The tier is decided by the change list in the release note**, not by judgement on the day: a listed change of the kinds above makes the release tier 2, otherwise tier 1.
- **Pre-flight probes** run in both tiers (`preflight.mjs`; `bench.mjs` runs it).
- **Judge only what changed**, both tiers: a card whose delivered spec (diagram JSON and body text), prompt, depth and judge rubric versions hash like a card of the last judged run keeps that run's verdicts (`--carry-from <judged run dir>`; its row is marked carried; the report counts judged and carried per judge kind). The judge cache, keyed by rubric version and the exact text the judge reads, carries the same way. A rubric version bump invalidates both. Measured 2026-11-09 (118 candidate against the 117 rerun): no whole card is byte-identical across generations because the prose is rewritten each time, so this saves re-judging a re-scored or interrupted run, not a new generation.

## How to read these results (owner review, 2026-11-08)

- **Temperature 0 (item 47) is a measurement fix, not a kind fix.** It makes a variance case (water cycle, 1 of 3) either 3/3 right or 3/3 wrong; a deterministic miss is diagnosable, a coin flip is not. The regression set after temperature 0 tells what is actually wrong.
- **The flow share (45 of 81 diagrams) is a smell, not a target.** Without a best-kind label on every card it is unknown how many flows are wrong, and pushing the number down is how test 9 happened (stricter wording cut correct binary layouts from 8/8 to 3/8). The regression set is the measure.
- **TCP handshake failed 3 of 3: the rule is not firing, not variance.** Temperature 0, the server diagram fixes and the structure-first rule do not touch it. Cheap fix first: the sequence line now reads "sequence whenever two or more named parties send things to each other (client and server, sender and receiver, a protocol, request and response)"; tested on the handshake alone. Only if that fails: one example per kind in the prompt (D), measured on the handshake and the long loops first.
- **Picture vs SVG is "solved" only once it holds at temperature 0.** The 3 misses in test 7 share one pattern (rule gap, not noise): "how does a volcano erupt / a solar eclipse happen / a four-stroke engine work" got a flow only. Fix: a "how does X work / happen" question about a physical object, place or natural event gets a picture and the process diagram.
- **Binary trees: "4/4 correct" covers only the wrong-use direction.** The test-9 regression was the other direction (binary where it fits); those 8 are re-checked after the next release before the binary rule is marked done.
