## What E0 added

- `packages/control-plane/src/explanation-models.js`: `resolveExplanationProfile(profileId, registry)`, `explanationProfileFor(env)` (server setting `EXPLANATION_MODEL_PROFILE`, empty = default `plan-default`), `explanationProfileBinding` (`{id, version, hash}`), `EXPLANATION_CANDIDATES` (inventory of Opus / Celeris / Cerebras / Gemini Flash with honest status). The default profile reads `LEARN_TASKS.artifact`, so its request equals the pre-profile request exactly.
- `learn-artifact.js`: `prepareArtifactAuthorRequest(…, {profile})` applies the profile when the written Explanation card is the only card on offer (direct `explanation` command and the Tutor roadmap `explanation` format); every other command keeps `LEARN_TASKS.artifact`. An unknown or unsupported profile is a plan refusal (`{result:'unsupported', message}`), never a silent default. The one existing repair uses the repair role's model (the author's unless the profile pins another plan model). The artifact result carries `profile: {id, version, hash}`.
- `roadmap/roadmap-generate.js`: the quote returns the profile binding; an accepted record that kept a binding dispatches with exactly that profile and sends nothing (`profile_changed`) when the registry no longer resolves to the same hash.
- `scripts/ci/check-map.json`: `explanation-models.js` mapped to its tests.
