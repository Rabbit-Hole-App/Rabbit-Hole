## Blunt summary

- Built and wired to real handlers: term pills with definition and Dig Rabbit Hole, the three suggested questions (Ask here, Ask in a new card), the bottom + with Ask a follow-up, the selection toolbar (Ask in chat, Highlight, Create note), the Add note menu row, curved bowed connectors for child cards and notes.
- Everything is gated on `block.interactions`. A card without the envelope (every card today, the switch being off) renders byte for byte as before: no wrapper element, no listener-driven toolbar, no blank row. `explanation-card-interactions.test.mjs` asserts it.
- **Not built (PENDING, needs the lead / a backend field):** the card-bound conversation. Ask here and the follow-up field send an ordinary Chat turn about the card; the reply appears in the Chat pane, not in a thread inside the card, and no conversation id is bound to (card, revision, user). See "Pending".
- Pill alignment is verified at render time against the canonical text; a field that does not align (typeset math, legacy Mermaid) is left plain rather than guessed.

## Pending, stubbed or not as specified (be blunt)

1. **Card-bound conversation (spec section 5, "Ask here and bottom follow-up"): NOT built.** Ask here and the follow-up send a normal Chat turn whose subject is the card (`canvas_target`). The reply lands in the Chat pane in the learner's current thread, not "in that card's approved thread", and no conversation binding is persisted on the card. Needs: a server-owned conversation bound to (saved card, revision, user) and a place on the card to read it. The captured `revision` and `actionId` travel in `about.selection.explanation` but the server does not receive or store them.
2. **Consumption is board state, not per user.** `block.interactionState` is saved with the card; on a shared board every editor sees the same consumption. The spec's "per user/card/revision" needs a per-user store.
3. **Child identity is not reserved.** Only the link id is derived from the action id (`explain-child-<actionId>`); the child's block id is generated at insert, and no retry/reconcile path exists for a lost insert. "Retrying the same action cannot create a second child/debit" rests on the existing `/explain` flow, which this lane did not change.
4. **Admission is the dispatcher's word, not the billing hold's.** For Ask here it is "the stream opened"; for Ask in a new card it is "the command ran without an error notice". A refusal that arrives after that (credits, safety) is shown by the Chat or the command notice, and the suggestions stay consumed.
5. **Dig: the revision is recorded only in the client's dive record** (`origin.origin_term`); whether the server keeps unknown record fields was not verified. A card that already has a Rabbit Hole is entered (`planDive`), not given a second hole for the new term.
6. **No Highlight removal control** (the spec names none). A stale highlight is omitted from the text; its record and quote stay in `block.highlights` with no reader.
7. **Fields that do not align get no pills and no highlight:** typeset math and legacy Mermaid fences (the canonical text holds the LaTeX or the fence source, the DOM holds the rendering). New cards use `rh-diagram`, which aligns. A pill in a closed section appears when it is opened.
8. **Copied helpers:** `contentRevisionInput`, `contentRevision` and `fieldText` are copied into `packages/web/src/explanation-interactions.js` because the control-plane module drags `learn-grade-jev.js` (the spend ledger, about 0.8 MB) into the browser bundle. A parity test guards drift. Better fix, for the lead: split those three pure functions into a leaf module both sides import.
9. **No e2e check written.** `check-map.json` maps the new files to the unit tests plus `card-context-menu-check.mjs` and `add-to-chat-check.mjs`. Browser acceptance is below.
10. **Shared and forked boards** carry `highlights`, `interactionState`, `parentCard` and `quote` as ordinary card/item fields; whether the board save, share or fork code strips unknown fields was not verified.
11. **Focus mode** and the Full layout were not examined; the follow-up field and the toggle are absolutely positioned under the card frame and may clip there.
