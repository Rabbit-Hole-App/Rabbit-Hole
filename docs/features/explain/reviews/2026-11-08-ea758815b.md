## What the two rungs contain

| Piece | Where | Behaviour |
| --- | --- | --- |
| Interactions envelope (E2) | `packages/control-plane/src/explanation-interactions.js` (new, pure) | Behind `EXPLANATION_INTERACTIONS=true` (default OFF, so today nothing changes). The Explanation tool also takes `questions` (exactly 3, distinct, non-blank, at most 120 code points) and optional `terms` (up to 6, one or two words, definition at most 160, anchor `{field, quote, occurrence}`), all in the existing ONE author call. They are validated against the FINAL card (accepted title applied, diagrams settled) in the same message as every other problem, so the one direct repair sees them all; the Tutor path (`repairs:0`) fails terminally with reason `explanation_bad_interactions`. The server then saves `block.interactions = {version, displayTextVersion, contentRevision, questions:[{id,text}], terms:[{id,label,definition,anchor:{field,quote,occurrence,start,end}}]}` with server-assigned ids (revision plus ordinal). Author-supplied ids, revisions and raw fields are never kept. |
| Canonical text and revision | same, `learn-primitives.js explanationFieldText` | One per-field display-text mapping (Markdown removed, whitespace collapsed, code points); term occurrences are whole-word and zero-based; overlaps and substring hits refused. `contentRevision` hashes a versioned serialization of title, body and sections only: a resize, move, id change or reload does not change it, an edit does (`interactionsCurrent`). |
| Text accounting | same | Questions and definitions are outside the teaching cap (separate allowance 6 x 160 + 3 x 120 = 1,320 code points, enforced by field limits); the cap is exact at 600/1,000/1,500 and fails one over, with a maximal envelope. |
| Highlighted route (E3) | `packages/web/src/tutor-diagrams/spec.js`, `flow.js`, `primitives.js` | Optional `highlightPath` on a `flow`: ordered node ids, 2 to 12, distinct, known, every step an existing directed edge, from the one start node to a node with no outgoing edge. The renderer draws that route in one fixed theme style (`PATH` blue wire, arrow head and ring; `data-tutor-path` markers), drawn over crossing wires; unselected branches stay neutral; the accessible description reads `Highlighted path: A -> B -> C`. Visible-text counting is unchanged (ids and the route are not teaching words). Saved diagrams without the field render identically. |
| Required trace (E3) | `explanation-visuals.js`, `EXPLANATION_GUIDANCE` | A flow request that says trace/follow/walk through/highlight gets `trace:true`; the card then needs a valid `highlightPath` (EX-07's "Trace a 25-year-old..." now requires it, replacing E1's caption-only substitute). The guidance names the field. |
| Illustration caption accounting (E3, GAP-03) | `learn-primitives.js explanationText`, `illustrationProblem`; `LearnPage.jsx markIllustration`; `illustration-target.js` | An attached illustration's caption and callout text count toward the cap. New cards save the `depth` they were written to (`block.depth`). When Add illustration marks a card, a card with no room for the caption is refused with a `toast()` before the plan can attach anything, and the lesson is never rewritten. Cards saved before E3 have no Depth, so they are not refused (ponytail comment). |

Reuse recorded: `toast()` from `ui.jsx` (the refusal), `TutorDiagram`/`layoutFlow`/`connector`/`box`/`diamond` (the route style is options on the existing primitives), `markedBlock`, `illustrationFrom`, `generateArtifact`'s existing repair, `learn-validation.js` tool-input validator.
