## Commands

From the repository root:

```
node benchmarks/explain/run.mjs --mode dry                                   # prints the plan; writes a dry run directory
node benchmarks/explain/run.mjs --mode dry --out "$TMPDIR/dry-check"         # same, outside the results root (no README row)
node benchmarks/explain/run.mjs --mode fixture                               # 4 fixture profiles x 8 cases + 5 calibration, about 2 s
node benchmarks/explain/run.mjs --mode fixture --profile plan-default,fixture-mixed --role repair=fixture-fast
node benchmarks/explain/run.mjs --mode fixture --resume <run-id>             # reconcile and finish an interrupted run
node benchmarks/explain/run.mjs --mode live                                  # refuses, exit 2, writes nothing
```

By default each run writes `benchmarks/explain/results/<run-id>/` and appends one row to `results/README.md` when it finishes. A bare `--mode dry` uses the registry default `plan-default` and so shows the real matrix: author and repair on the repository model, one author call and at most one repair call per direct attempt, zero evaluator model calls, cost bound unknown because the profile carries no pricing key, cerebras and gemini-flash unsupported, celeris dev-route only.

## Real versus stubbed

REAL, and exercised by the tests:
- Profile resolution, role overrides and profile hashing go through `explanation-models.js`. Every fixture attempt runs through the REAL `prepareArtifactAuthorRequest` and `generateArtifact`: the production validator, the required-visual check, the Depth cap, the diagram parser and the one repair all run behind the double. The request is the real request (hash and model are recorded per attempt).
- Usable-card latency, author time, repair time and validation time are measured with an injectable clock; the timeout is enforced on that clock.
- Attempt and call identity are written before dispatch. `calls.jsonl` is one line per state change (`dispatched`, then `settled` or `reconciled`); the last line per call id wins. Results are appended as attempts finish. Resume never re-dispatches an attempt that already dispatched a call (it is recorded as `interrupted`, usage unknown, and stays in the denominator); it skips attempts that already have a row.
- Secrets: values of secret-looking environment variables and bearer tokens are redacted from every write; the manifest records how many values were removed, never what they were. Credential NAMES (`credentialRef`) are kept.

STUBBED or NOT BUILT, bluntly:
- `live` does not exist beyond the refusal. There is no network adapter for any provider; the three response shapes are normalization fixtures only.
- Every fixture "model" reply is scripted text. The fixture run's latency, cost, factual and repair numbers describe the scripts. They are not model results and the committed report says so on its first line. Prices in the fixture config are synthetic; the registry carries no real pricing, so the baseline cost is `unknown`.
- The provider shapes and the synthetic ids are NOT verified against any real provider. Whether Gemini `candidatesTokenCount` includes thinking tokens is explicitly unverified (marked `shortcut:` in code). No Cerebras or Gemini profile is registered in the product; a config profile naming another adapter is refused with `adapter_unsupported`.
- The evaluator is a text-pattern check against frozen facts. It proves the seeded defects are caught and clean answers are not flagged; it cannot establish the truth of open-ended prose from a real model. `rubric.reviewRequired` is set on every rubric; disputed facts need an independent or human reviewer (EXP-09-C05). The model-based evaluator is a stub that refuses without an evaluator profile and a cap. Blinding of provider identity is only structural (the deterministic evaluator is never given it).
- Not measured: first-output latency, client save, render and Send-to-usable-card on the real client path. The harness measures from the constructed author request to the validated card. Tutor-entry cases (repairs 0) and image-attachment cases are not in corpus v1; only the Tutor call ceiling is computed.
- Cache hit/miss separation is a recorded policy (every fixture call is a miss), not exercised.
- Winner selection is not implemented: every report says "No winner" and why. `thresholds.json` was written before any run, but nothing consumes it yet; ranking against it belongs to the first authorized live run.
- Fixture timestamps (`startedAt`, `endedAt`) are real wall time while durations come from the virtual clock, so they do not add up; this is stated in the manifest limitations.

## Findings about the product that matter for the real benchmark

1. A prompt that merely names a decision tree derives a REQUIRED flow diagram. `DIAGRAM_WORD` in `explanation-visuals.js` includes `decision[- ]?tree`, so a prose question such as "which split would a decision tree choose" gets `requiredVisuals: diagram` and a prose-only answer fails with `required_visual_missing`. I found this while building the EX-02-style prose-only cases and reworded the corpus prompt ("a tree-growing classifier"). It is a wording heuristic, already marked `shortcut:` in that file; it is not changed here. It will matter for any decision-tree topic in a live corpus.
2. A profile that `extends` another and overrides only `author` keeps the BASE profile's repair role, not its own author. Verified: author `synthetic-x`, repair `claude-opus-5`. This is consistent with "a one-role override changes only that role", but a one-role substitution in a benchmark matrix must say so, and the fixture profiles here set both roles explicitly.
