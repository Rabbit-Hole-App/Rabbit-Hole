### 1,343 against 1,323

They count different things. **1,343** is the number of distinct JSON texts across the reference slots and the kind-gallery files (the same on ab40f5dc9, b29b6bdd7 and the tip; 117 duplicates among the 1,460 slots; it leaves out the 22 `examples.json` entries and the templates). **1,323** is not a count of distinct JSONs: it is the number of slots that `everySpec` iterates in `calculation-declarations.test.mjs`, which takes for each of the 492 references `spec`, `detailSpec`, `template` and every depth's `spec`, `detailSpec` and `template`, with no gallery, no gallery-depth, no single variant and no de-duplication. On feat/same-json 953a9ea55: 1,317 reference slots + 6 `template` entries (top-k reference, overview, standard, deep; softmax; mean baseline) = 1,323, which is the full-build report's "1323 stored specs in 492 references all parse". On the tip, top-k being parked, the same test counts 1,317 + 2 templates = 1,319 slots (1,226 distinct texts); on ab40f5dc9 it would count 1,317. So 1,323 is neither 20 short of the spec's 1,343 nor a different count of it: it adds 6 templates and leaves out the gallery and the singles. The full-build report did not claim that all 1,343 parse; the run above is the first that shows it.
