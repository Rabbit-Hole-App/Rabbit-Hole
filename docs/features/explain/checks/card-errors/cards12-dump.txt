When we build a bootstrap sample of size $n$ from $n$ rows by drawing with replacement, any single row is left out with probability $(1 - 1/n)$ on one draw.

Across all $n$ independent draws, the chance that a specific row is never chosen is $(1 - 1/n)^n$.

Look for the curve approaching the horizontal reference line in

```rh-diagram
{"version":1,"diagram":{"title":"Bootstrap omission by training set size","caption":"Worked example. Omission with replacement is $(1-1/n)^n$. Samples rounded. Limit $1/e\\approx 0.368$ gives expected coverage $1-0.368=0.632$.","kind":"coordinate-plot","x":{"label":"Training rows n","min":1,"max":10,"integerTicks":true},"y":{"label":"Chance a row is omitted","min":0,"max":0.4},"series":[{"label":"Omission after n draws","kind":"line","points":[{"x":1,"y":0},{"x":2,"y":0.25},{"x":3,"y":0.296},{"x":4,"y":0.316},{"x":5,"y":0.328},{"x":6,"y":0.335},{"x":7,"y":0.34},{"x":8,"y":0.344},{"x":9,"y":0.346},{"x":10,"y":0.349}]}],"annotations":[{"kind":"reference-line","label":"Omission limit","axis":"y","value":0.368}]}}
```

, showing how the omission chance stabilizes near $0.368$ as $n$ grows large.

As sample size $n$ increases, this expression approaches the limit $1/e \approx 0.368$ using the standard definition of the exponential constant.

Because the omission probability is about $36.8\%$, the expected proportion of unique training rows included in the sample is the complement, $1 - 0.368 = 0.632$ or about $63\%$.

################ 8 public-key-encryption balanced {"provider":"google","model":"gemini-3.5-flash-lite"} google-low planner null null repaired false
When Alice wants to send a secret message to Bob over an insecure channel, she uses Bob's public key to encrypt the data.

This key scrambles the message into ciphertext using a one-way mathematical trapdoor function that is easy to compute forward but hard to invert.

```rh-diagram
{"version":1,"diagram":{"title":"RSA Encryption Sequence","kind":"sequence","actors":[{"id":"alice","label":"Alice"},{"id":"bob","label":"Bob"}],"messages":[{"from":"bob","to":"alice","label":"Send public key"},{"from":"alice","to":"bob","label":"Send ciphertext encrypted with public key"}]}}
```

Only Bob possesses the corresponding private key required to reverse the operation and recover the original plaintext.

The security relies on computational asymmetry, such as the difficulty of factoring large prime numbers.

Because the public key cannot decrypt the ciphertext it generates, Bob can safely share it with anyone without compromising his private credentials.

################ 10 bst deep {"provider":"google","model":"gemini-3.5-flash-lite"} google-low planner null null repaired false
A binary search tree organizes keys hierarchically so that each node satisfies a strict ordering invariant. For any given node, all keys in its left subtree are smaller, and all keys in its right subtree are larger.

```rh-diagram
{"version":1,"diagram":{"title":"Insert 7 into the binary search tree","caption":"7 < 8, 7 > 3, and 7 > 6. The empty right slot below 6 receives 7.","kind":"tree","layout":"binary","nodes":[{"id":"eight","label":"8"},{"id":"three","label":"3","parent":"eight","side":"left","edgeLabel":"7 < 8"},{"id":"ten","label":"10","parent":"eight","side":"right"},{"id":"one","label":"1","parent":"three","side":"left"},{"id":"six","label":"6","parent":"three","side":"right","edgeLabel":"7 > 3"},{"id":"seven","label":"7","parent":"six","side":"right","edgeLabel":"7 > 6","detail":"Inserted key"}],"highlightPath":["eight","three","six","seven"]}}
```

Search operations begin at the root node and compare the target key against the current value. If the target is smaller, the search proceeds down the left child edge; if larger, it moves to the right child.

This branching structure guarantees logarithmic time complexity $O(\log n)$ for searches, insertions, and deletions in a balanced tree. Each comparison halves the remaining search space.

################ 12 gradient-descent deep {"provider":"google","model":"gemini-3.5-flash-lite"} google-low planner null null repaired false
Gradient descent is an iterative optimization algorithm used to find the minimum of a differentiable objective function $L(w)$.

Starting from an initial parameter estimate $w_0$, the algorithm updates the weights by taking steps proportional to the negative of the gradient.

The update rule is defined as $w_{t+1} = w_t - \eta \nabla L(w_t)$, where $\eta$ represents the learning rate.

```rh-diagram
{"version":1,"diagram":{"title":"Worked example of gradient descent steps","caption":"A descent path on a quadratic loss function.","kind":"coordinate-plot","x":{"label":"Weight 1","min":-3,"max":3},"y":{"label":"Weight 2","min":-3,"max":3},"series":[{"label":"Outer loss contour","kind":"line","points":[{"x":-2,"y":0},{"x":-1.4,"y":1.4},{"x":0,"y":2},{"x":1.4,"y":1.4},{"x":2,"y":0},{"x":1.4,"y":-1.4},{"x":0,"y":-2},{"x":-1.4,"y":-1.4},{"x":-2,"y":0}]},{"label":"Inner loss contour","kind":"line","points":[{"x":-1,"y":0},{"x":0,"y":1},{"x":1,"y":0},{"x":0,"y":-1},{"x":-1,"y":0}]}],"annotations":[{"kind":"vector","label":"Step 1","from":{"x":2.5,"y":2},"to":{"x":1.4,"y":1.1}},{"kind":"vector","label":"Step 2","from":{"x":1.4,"y":1.1},"to":{"x":0.6,"y":0.5}},{"kind":"vector","label":"Step 3","from":{"x":0.6,"y":0.5},"to":{"x":0,"y":0}}]}}
```

The choice of the learning rate $\eta$ governs how large each adjustment is during training. If $\eta$ is too large, the updates may overshoot the minimum and diverge.

If $\eta$ is too small, convergence requires excessive computational steps.
