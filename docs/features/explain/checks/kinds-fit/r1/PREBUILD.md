## Contradicted or not buildable as written (with what I will do)
1. **Tensor has no cell positions to pass through.** Spec 2 table: "tensor-layout.js returns `cells`". `cells` is a NUMBER, the y offset of the cell grid inside the strip (tensor-layout.js:63 `cells: top`, :76 `cells: 0`, :85 `cells: labelHeight + scene.cells`). There are no per-cell rectangles. Amendment 1a asks for geometry "for the three layouts that already compute positions (flow nodes and edges, plot plotBounds, tensor cells)": flow and plot are real, tensor is not. I return no geometry for tensor in this delivery and say so; per-cell geometry is new work for the tensor round.
2. **Flow geometry is not `nodes`/`edges` of `layoutFlow`'s top level.** It is `geometry: { width, height, nodes, edges }` (flow.js:607, built by `flowGeometry` flow.js:611-623), already registered as `layouts.flow = layoutFlow` (layouts.js:275). The entry can pass it through with the title offset added; edge `points` and node boxes are in the layout's coordinates (title offset = `titleHeight`).
3. **`box.height` is not the layout's height.** The entry adds the title block above and the caption below (TutorDiagram.js:27-30), so the layout must be given the content height `box.height - titleBlock - captionBlock`, and the title and caption wrap at the DRAWN width, which may be larger than `box.width` when the kind's minimum is wider. I do two passes in the entry (box width, then the drawn width when min is wider). A new internal option key `contentHeight` carries it; it is not part of the public three keys.
4. **`fitCaption` can widen the picture** (primitives.js:158-163: a caption formula wider than the scene sets the width). With a box, `box.width` is the width (amendment 3); a caption formula wider than the box counts in `min.width` (unless `parts.caption` is false).
5. **Inline sizes beyond the file constants** (the spec says "plus numbers written inline (16, 17)"; the full list for the plot, all in ml-plot-layouts.js and one other file): TICK 15 (:13), SMALL 12 (:9), CURVE_LABEL_SIZE 15 (:127), axis and y titles 16 (:244, :256-258, :289), value labels 15 (:494-498), legend pill text 12 and pill height 22 (legendPills ~:98-114), callouts and end labels SMALL, **plot-ticks.js:3 `const SIZE = 15`** (a different file: tick wrapping and spacing, `fits`, `format`), and `tickSpan` (:218) uses TICK. These constants are also used by the bar-chart, histogram and other layouts in the same files; I read the new table only inside the plot functions and leave the module constants as the defaults for every other kind, so no constant changes value.
6. **"Every text in it is 14 px" cannot be guaranteed by the layout alone.** `wrap()` shrinks a line one font step when a single word is wider than its box (primitives.js:60-66 `fitLines`, `lines.fontSize`), and a LaTeX formula is scaled by `mathScale`. I will make the worked examples assert the font sizes found in the SVG and report any that differ; the layout widens the boxes it controls (tick label width, end-label gutter) before a word would be shrunk, but a caller's long word in a fixed box can still cost a step.
7. **Fixed token-links rows make 632 x 152 unreachable.** Today the picture is 632 x 315 (title 39 + panel 276; measured: probe renderTutorDiagram at 632). The panel is: pad 12, inset 12, query heading, source chips 56 tall from y=34, a row gap `max(86, round(rowWidth x 0.16))` (token-links-layout.js:89 `targetY`), target chips 56, footer, pad. With the row gap reduced to what a weight badge (24 px) and arrowheads need (about 48), the minimum at 14 px is about 240 px, above the 152 asked. Spec 6.2 allows "or `min` if the six tokens at 14 px need more": the 6.2 call returns min (about 240 tall), and the image at "one box smaller than min" is the same. I will not shrink chips below 56 (text and boxes do not stretch down) and say so.
8. **Pendulum spec is not in this repo** (6.1 cites `proof/layout-b35`, the /interactive repo). I use a reconstruction: two line series, x 0 to 8 s, y -25 to 25 degrees, a title (probe above: 408 x 420.5 today, the spec says 408 x 451; the difference is the series names and legend in the real card).
9. **`min` cost.** Computing `min` needs extra layout passes for the plot (width search for tick crowding, a floor-height pass). To keep `/explain`'s own calls at today's cost, `min` is a lazy property on the returned object (computed on first read, memoised); a caller that destructures `{ width, height, element }` pays nothing.
10. **Kinds not done get no options.** A kind not done yet must ignore `box` and `sizes` (spec 5): the entry passes the options only to kinds on the done list (coordinate-plot, token-links), so a composition (panels, comparison panels) never hands a parent's box to a child. `parts.title` and `parts.caption` are applied by the entry for every kind. `min` for a kind not done = its drawn size.
11. **Width floor in box mode.** Spec 3.1 says the 320 to 720 clamp and the kind's minimum width do not apply with a box, "the kind's real minimum does". I define the real minimum of the plot as: left margin + a 120 px plot area + right margin (+ end-label gutter), widened until no two x tick labels touch (the existing `coordinatePlot` crowding loop) and until every legend pill, curve name and callout the placement code accepts fits; and a plot-area floor of 96 px tall (the default stays 240 with no box). For token-links: the narrowest width at which the chip rows wrap to one column (2 x (pad + inset) + label gutter + one chip), taller as it wraps. These two floors are my choice; the spec does not give numbers (computed how, per kind, in the report).
12. **Rule 4 check.** `FrameFigures.jsx` (explain-program/) calls `renderTutorDiagram(spec, box.w)` and `explanation-card-width.js` calls it too: both keep working unchanged (no third argument, byte-identical output; `naturalSize` TutorDiagram.js:60-66 unchanged).
