## Depth mapping (as the code does it)

- Request depth names: `brief | balanced | detailed` (`chat-depth.js` `validDepth`); a request with `balanced` sends no `depth` at all (`learn-artifact.js:474`, `depth !== DEFAULT_DEPTH`), so `input.depth` is undefined for balanced.
- Reference side: `DEPTH_KEYS = { brief: 'overview', balanced: 'standard', detailed: 'deep' }` (`explanation-references.js:95`); `level = DEPTH_KEYS[depth] ?? depth` (`:110`, so the legacy names overview/standard/deep also work; an undefined depth gives level `undefined`, i.e. the base reference); `atLevel(ref) = ref.depths?.[level] ? { ...ref, ...ref.depths[level] } : ref` (`:111`). The reference's own top-level `spec` is its standard version: 292 of the 459 non-`general` references carry `depths` (many only `overview`/`deep`, base = standard). The spec at a depth is therefore `atLevel(ref, level).spec`; `detailSpec` (the second figure of a `deep` variant) is NOT part of G1 ("{ id, spec } only").
- Gallery side: `GALLERY_LEVEL = { brief: 'overview', balanced: 'standard', detailed: 'deep' }` (`explanation-planner.js:115`); `planShape` reads `entry[level] ?? entry.standard` (`:117`) from `kind-gallery-depths.json` (the legacy depth names overview/standard/deep are NOT valid there: `validDepth('overview')` is falsy, so the default standard is used; `test/explanation-planner.test.js:73` passes those names).
- Two-panel references: `preferSingleVariants` (`explanation-references.js:150-158`) swaps a `panels` reference (always) or a two-panel comparison / visual transformation (unless the planned kind is comparison or transformation) for its `-single` variant (`reference-single-variants.js`: authored specs in `reference-single-specs-a/b.js` etc., or the LAST panel of a two-panel reference, `:17-20`). The `-single` variant has no `depths` and no `vary`: it is the same spec at every depth and is never varied except by `{{d:}}` tokens (`sampledSpec(single, seed)` -> no `vary`, `:156`). So "the single-diagram spec AT THE CARD'S DEPTH" does not hold for these (35-36 references); see the "+n" figures.

## Eligibility rule as implemented (g1.mjs)

For each library reference whose id does not match `^(shape|general)-` (`general-` = 10 library entries, `reference-library.js:71-77`; `shape-` = 0 library entries: `shape-*` ids are synthesized at `explanation-references.js:31` and `explanation-planner.js:118`, never in the library):
1. `m = atLevel(ref, level)`; `spec = m.spec`.
2. If `spec.diagram` is composed (`kind === 'panels'`, or `kind === 'comparison' && variant === 'panels'`, or `kind === 'transformation' && variant === 'visual'`): use its `-single` variant's spec if one exists (`singleDiagramReferences`, 43 exist for the library; counted in the "(+n)" column only), else the reference has no single diagram (4: ml-raw-log-distributions, ml-regression-error-metrics, ml-repeated-sample-fits, ml-time-series-additive-residuals; 3-panel comparisons: `needsAnswerPanel`, `reference-single-variants.js:17` keeps only two-panel ones) and is out.
3. `kind = spec.diagram.kind`.
4. Bundle test, the code's own: `diagramBundle({ references: [{ spec }], requiredKinds: [kind] })` (`explanation-references.js:207`) against `diagramBundle({ references: [], requiredKinds: [kind] })`; any difference in `quant, fresh, panels, states, tensor, tokenLinks, blockStack, blockStackPanels, compactPlots, tensorHosts, parallelPaths` excludes it. The kind itself is passed as required, so a kind that needs a flag (tensor, token-links, block-stack, a NEW kind, a QUANT kind) sets it on both sides and is not excluded for it. How each is detected, from the code:
   - tensor payloads: `tensorHosts` = flow / relationship / transformation whose nodes carry `tensor` (`usesNodeTensors`) or whose items are not strings (`usesTensorItems`) (`illustration-kinds.js:2-7`, `explanation-references.js:210`).
   - panels / visual states: `d.variant === 'panels'`; `d.kind === 'transformation' && d.variant === 'visual'` (`:212`); `blockStackPanels` (`:216`). Handled by step 2 (a composed reference never reaches the bundle test unless its `-single` variant does).
   - compact plots: `coordinate-plot` with any `series[].samples` (`compactPlot`, `:200`, `:217`).
   - parallel paths: `flow` with `highlightPath[0]` an array (`usesParallelPaths`, `illustration-kinds.js:8`).
5. The example would go out as `{ id, spec }` only (no `useWhen`, no `detailSpec`), so `detailSpec` is not tested.
