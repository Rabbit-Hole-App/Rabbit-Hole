## 4. The spend bound (quote, one-call budget) and the examples block

How the bound is made:
- `boundOf(body, route) = toMicros(requestSpendBound(body, route.model, provider))` (`roadmap-generate.js:29`; `subscription` priced as anthropic). `requestSpendBound` (`control-plane/src/learn-spend.js:14-39`): UTF-8 bytes of `JSON.stringify(body)` (system, tools = the whole author schema bundle, messages) + 1,000 framing, as INPUT TOKENS at the input rate (x1.0, x1.25 or x2 only with `cache_control`), plus `body.max_tokens` at the output rate; images / PDFs / unpriced -> null. One byte = one token: conservative.
- Quote: `quoteRoadmapCard` (`roadmap-generate.js:73-83`): `author = boundOf(prepared.body, route)`; `boundMicros = author + figuresBoundMicros(env)` for an explanation (`:79`); `figuresBoundMicros = FIGURES_MAX (2) x FIGURE_ATTEMPTS (3) x image reserve` (`explanation-figures.js:19,18,33`; 120,000 micros at the reservation the test uses, `test/explanation-layout.test.js:229`; 0 when no picture can be priced). Frozen in the snapshot at Accept (`roadmap-run.js:99`) and set as the hold (`roadmap-store.js:255`).
- Dispatch: `meter` (`roadmap-generate.js:109-122`): ONE author call (`ROADMAP_LIMITS.calls.generationPerCard = 1`, `roadmap-policy.js:27`; the counter `call` is shared by every fast-chain step because `meterStep` wraps each step with the same meter, so a provider fallback is refused: `operation_budget` `:111`, `:129`); repairs 0 (`roadmap-generate.js:68`). Then, only when the record has a fingerprint: `boundOf(body) <= rec.boundMicros` else `request_over_bound` (`:116`). NOTE the compared sides differ: the left is the author body alone, the right is `author + figures`, so with pictures priced the check is lenient by up to the figures part (120,000 micros), with no picture price it is exact.
- The body measured is the Anthropic-shaped `prepared.body` (before `stepRequest` turns it into the provider request: `explanation-fast-chain.js:133-146`); the ledger admits and reserves the provider request actually sent (`spendTransport`, `explanation-fast-chain.js:218`) out of the card's allocation (`learn-spend-ledger.js:117-143`).

The examples block (`diagramReferenceContext`, `explanation-references.js:173-187`): inside `body.system` (`learn-artifact.js:151`). Limit: `out.length + line.length <= MAX_CONTEXT` (14,000 characters of unescaped text, `:10`, `:184`), 3 lines (`:181`). In the measured JSON, every `"` and newline costs 2 bytes, a non-ASCII character up to 3. Measured with the real quote on a step record (g6bound.mjs; padded the system by 14,000 characters):

| profile (provider, model) | bare quote (no reference) | one-step quote with 2 refs selected (1,811 chars block) | +14,000 chars ASCII | +14,000 chars, all `"` (2 bytes) | +14,000 chars, 3-byte |
|---|---|---|---|---|---|
| `roadmap-gemini` (google gemini-3.5-flash-lite; `GEMINI_API_KEY` set; `cardProfileId`, `roadmap-generate.js:33`) | 16,661 micros (body 29,534 bytes, max_tokens 3,000) | 21,552 (body 45,839 bytes) | +4,200 (25.2% of the bare quote) | +8,400 (50.4%) | +12,600 |
| plan-default (anthropic claude-opus-5, no Gemini key; full schema, not bundled) | 735,725 micros (body 126,145 bytes, 123,137 of them the schema, max_tokens 4,000) | 746,500 (body 128,300 bytes) | +70,000 (9.5% of the bare quote) | +140,000 (19.0%) | +210,000 (28.5%) |

- Real lines are much smaller than the cap: the biggest single library reference line is 2,423 characters, median 803 (none over 14,000; `{ id, spec }` lines of the G1 pool are at most about 1,254, G1.md); three such lines plus a heading are about 5,000 characters, i.e. roughly +1,500 micros on the Gemini profile.
- The quote already moves with steering: 16,661 vs 21,552 micros above is two selected references plus the schema flags they set (`diagramBundle`, `explanation-references.js:207`); a G5 single-kind bundle shrinks the tools part of the body (a flow-only bundle is 28 properties against 136 for the CORE bundle) so the bound falls too.
- What the quote is built from today: no seed, no plan (`planned: true`), so it holds no G1 examples and the bundle of the unplanned request; a seeded, planned dispatch body differs in system text, tool description and schema, which is why the equality could never hold and the bound check is the only one that can fail on size.
- Where the 14,000 cap, the bound and the allowance meet: the allocation for the card is exactly `boundMicros` (hold = quote x 1 slot, `roadmap-money.js:76-77`), so a body that costs more than the quote is refused either by `request_over_bound` (`roadmap-generate.js:116`, only with a fingerprinted record) or by `consumeStepAllocation` (`learn-spend-ledger.js:119-120`) when the provider request's own bound exceeds what is left; records accepted before a release keep their old fingerprint and bound (the snapshot is immutable), so the check applies to them too.

## 5. Archive reachability for G6 (spec section 3)

- The AR-1 record is written only by `artifactFetch` (`learn-artifact.js:457-459`, `archiveExplanation`, `control-plane/src/learn-storage.js:14-21`, R2 `explain-archive/<day>/<id>.json`; any `trace` field goes in, no whitelist; written even when the request fails, logged never thrown). Fields today: `id, at, ms, release, userId, app, board, request{ command, args, selection, hasContext, depth, sourceRefId }, plan, plannerKind, references (ids, shape excluded), shapeId, models, requestSeed, answers, tokensFilled, bodyWithTokens, outcome, repaired, profile, steps, error, returned, stylePreamble` (`:201`, `:226`, `:297`, `:457-459`).
- A roadmap card has no archive record (no `trace` at `roadmap-generate.js:127`) and neither does an inline card (`learn-inline.js:208`): "a card is reproducible from its record" cannot hold for them as the code is; the roadmap keeps only `learn_roadmap_calls` rows (op id, provider, model, `request_fingerprint`) and the accepted snapshot.
- Ids that exist at roadmap dispatch and are stable across a replay: `rec.cardId` (`result.card_id`, `roadmap-run.js:124`), `proposalId`, `proposalVersion`, `retry`, the operation key (`roadmap-money.js:19-21`, `roadmap-contract.js` `operationKey`). A crashed call is never retried blind (`roadmap-run.js:111-112`), so a dispatch-time seed need not survive a replay.
