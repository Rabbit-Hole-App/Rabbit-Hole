## The two open questions (read-only)
1. Is the plain-text formula fallback ever shown to a learner? Caption and label text with formulas is drawn twice in an SVG `<switch>`: a KaTeX child behind `requiredExtensions="http://www.w3.org/1999/xhtml"` and a plain-text child made by `plainMath` and `nativeLine` (captions primitives.js:198-222, switch at 218; labels primitives.js:153-154; formula-to-text helper primitives.js:180-197). The app draws these SVGs only live in the browser (TutorDiagram via Md.jsx rh-diagram, CodeExplainCard.jsx:131, LearningBlocks, IllustrationFigure.jsx, explain-program/FrameFigures.jsx:95); no export, share preview or rasterisation of a TutorDiagram SVG was found in src (card-thumbnail.js and learn-group-shot.js draw canvas shapes only). In headless Chrome the bootstrap-coverage SVG's KaTeX child has width 362 and the plain-text child width 0, so the fallback is not shown. The flattened "(1 - 1/n)n" in the lane's renders is KaTeX markup drawn without the KaTeX stylesheet in the render page, not the fallback. A learner sees the fallback only in a viewer that rejects the XHTML switch (a standalone SVG viewer or a raster tool); none exists in the app. So: no ticket needed for learners.
2. The middle dot in "A . d=2": the real card's SVG font is 'Inter, Liberation Sans, Arial, sans-serif' (teaching-theme.js:30, applied at TutorDiagram.js:93; non-teaching kinds use Arial, Liberation Sans).
