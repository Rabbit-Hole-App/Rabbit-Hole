# PLT-3(A) curve labels (commit 6d84661a6 on feat/visual-sprint-2-plt, file ml-plot-layouts.js)

Rule as built (defaults only, no spec/schema/reference change, palette only): a coordinate-plot of 2 or 3 line series (all kind "line", not closed, no end label, no low/high interval) has no legend. Each name stands beside its curve: bold (700) 14 px, in the series ink (the darker weight of the series colour, the same one the legend pill text uses: the plain fill colour is too light to read as text on the cream), at the sample where the curve is farthest from the other curves (distance in px to the nearest other curve at that x; ties: the rightmost), 18 px outward (away from the nearest other curve, along the curve's normal), with a 1.5 px leader in the series fill colour and the standard 12 x 8 head landing on the curve. If any label would touch a curve, another label or a note/callout, or leave the plot, no label is drawn and the legend pill returns for the whole plot. One series, 4+ series, scatter/step/stem/closed series, an end label or an interval: the legend, as before.

How the formula sampler was enabled in the local render: EXPLANATION_FORMULA_SAMPLER is read only server-side (control-plane learn-artifact.js: formulaSamplerEnabled(env)), where it makes the author offer formula series and then runs fillFormulaSeries. render.mjs calls that same function (packages/control-plane/src/explanation-formula-series.js) on the spec: that is the flag-on path, no environment variable is needed to render. Flag off: the same plot with hand-written points (9 samples a curve, 3 decimals): curves-hand-*.

Files: curves-formula-before/after-408/720 (Normal / df = 5 / df = 1 by formula, 24 samples, smooth, reference line x = 0); curves-hand-before/after-408/720 (hand-written points); curves-separate-after-408/720 (extra: three separated normals); hunk.diff; render.mjs.

What the renders show:
- Normal / df = 5 / df = 1: the three curves differ by at most 13.5 px (Normal 0.40, df 5 0.38, df 1 0.32 at the peak) and the middle curve (df 5) has no clear side: its label would sit between two curves. At 408 AND 720 a label fails the touch test, so the legend stays (both before and after look the same; the label names are "Normal", "df = 5", "df = 1"). This is the fallback of the rule, not a bug: it needs curves that are not nested this tightly.
- Hand-written points: the same (legend).
- curves-separate (extra spec of mine: three normals at -3.5, 0, 3.5, x -6..6, y 0..1): labels appear at 720 (Left / Middle / Right, each above its peak, leader on the curve). At 408 the 280 px plot is too narrow for the label boxes beside the peaks (the leftmost label leaves the plot or the Middle one touches a neighbour), so the legend stays at 408.
- x ticks on these plots are -3, -2, 0, 2, 3: the tick generator decides, I did not set integerTicks (that would be a spec change).
