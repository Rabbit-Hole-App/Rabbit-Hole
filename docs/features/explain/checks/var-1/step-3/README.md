## What was built
- `requestSeed`: the artifact route makes one UUID per request (explain, explanation and walkthrough commands), passes it in the generate input and puts it on the archive trace, so every archive record, success or failure, carries it. `prepareArtifactAuthorRequest` reads it from the input, hands it to reference selection and returns it; `generateArtifact` records it on the trace.
- `packages/web/src/tutor-diagrams/random.js`: xmur3 + mulberry32, a deterministic source from a string seed.
- `vary.js`: `varySpec(spec, vary, seed, id)` redraws the paths of `ref.vary` (`{ path: [min, max, step] }` with an optional 4th element, an order path: the min is bumped to that path's value, so q1 <= median <= q3 holds by construction; the lint checks the order path's range statically). Value = min + k * step, decimals of min and step; one generator per reference from `seed|referenceId`. After the draw every derived field is set to what its inputs give (`refreshDerived` in `derived.js`, walking child diagrams through `childDiagrams`, now exported by `spec.js`); a set that must add to 1 is drawn raw and normalised by the existing fill; `{{d:path}}` and `{{d:path|k}}` in the reference's text are printed as the sampled number (also for an unseeded request, so the author never sees a raw token and a copied label cannot leave a token in a figure).
- `explanation-references.js`: `sampledSpec` runs before `parseTutorDiagram` where a selected reference becomes `compact`, and in `preferSingleVariants` for a one-diagram swap. A part of a composed reference (`referenceVariants`) drops `vary` (the paths walk the whole reference). A failed draw never fails a request: one `explanation_vary_failed` log line and the reference goes out as written (tokens printed if they can be). `selectWithSteer` and `selectForAuthor` take `seed` and an optional `from` list (tests inject a fixture; the library array is frozen).
- `varyProblems(ref)`, the lint: a bad entry, a path that is not a number, an order path that is not listed before it or whose range tops this one; and cited numbers: the number a `vary` path holds, and every number a derived field of the diagram holds, must not be typed in the reference's text (any string of the spec and `useWhen`) unless written as a token. Test over the whole library (passes: no reference has `vary`).
