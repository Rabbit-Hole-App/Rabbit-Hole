# Item 3: softmax recompute for list transformations

Where: packages/web/src/tutor-diagrams/spec.js checkSoftmaxList (called from validateDiagram case 'transformation', the list branch). Why there: that branch already reads the list items and links with the `issue(path, message, params)` callback that carries params; ml-composition-spec.js only checks the structure (list vs visual variant) and has no item parsing.

Rule: title or operation says softmax, every before/after item parses as a plain number (also "z_1 = 2.0", "Score: -1", "$0.5", "70%"), same item count: after_i = softmax(before)_i within HALF A UNIT of the decimals written for THAT item (percent: half a percent unit) + 1e-9. Issue names the correct value of every item (at least two decimals), tagged arithmetic, path after.items.
Gate (Reviewer correction, applied before this commit): title, caption, operation or any label (before/after label, link labels) mentioning temperature, scaled, scaling, masked, causal, log-softmax / log softmax (case-insensitive) or "T =" / "T=" (capital T, standalone) turns the recompute OFF; then the only check is that the after values sum to 1 within the sum of their half-units (= half-unit x item count at equal decimals) when the title or caption says probabilit(y/ies).
