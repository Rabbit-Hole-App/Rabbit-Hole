# Item 2: failedOn per archive step

Before: a step record was { provider, model, outcome, repairs, repairedAt?, issues? }; a step whose first answer failed validation and whose repair failed arithmetic showed only outcome 'arithmetic'.
After: generateArtifact collects `failedOn` (learn-artifact.js, one entry per failed answer: 'arithmetic' when the failure is explanation_bad_numbers, else 'validation_error'); it is returned on a validation_error and on a delivered artifact that needed repairs; explanation-fast-chain.js note() copies it onto the step (only when non-empty). Existing fields unchanged. Examples (tests): ['arithmetic','arithmetic'] two repairs failing arithmetic; ['validation_error','arithmetic','arithmetic'] mixed; an artifact repaired once after an arithmetic miss carries failedOn ['arithmetic'] with outcome 'artifact'; a clean first answer has no failedOn.

Readers: NEITHER the card-errors audit scripts (/c/s/sprint2-evidence/card-errors/*.mjs, they read cards-all.json and never touch steps/outcome) NOR archive-numbers.mjs filtered on a step outcome 'validation_error' (archive-numbers filters r.outcome === 'artifact' and picks the model from the step whose outcome is 'artifact'). So nothing was silently dropping 'arithmetic'. Change made: archive-numbers.mjs gets stepFailures(r) (failedOn when present, else a step outcome of arithmetic or validation_error) and a totals.answerFailures tally + one row in the Totals table; --selftest asserts it ('selftest ok'). No other script touched; the real R2 run was not repeated (needs credentials).
