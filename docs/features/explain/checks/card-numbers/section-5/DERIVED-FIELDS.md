## Top 5 recommendations

1. Merge the card-numbers box-fence check (cn 5c9da7620, checkBoxes :138-143 plus the arithmetic repair route). It is built and is the only fence rule. Add the whisker-inside-fence add-on later (P3).
2. Build the softmax recompute in transformation (per-item half-unit tolerance, gated against temperature/scaled/masked). Highest measured rate (6.1% of numeric transformation cards, 6 independent cells, 2 prompts), and the repair works because the message names the correct numbers.
3. Build the bootstrap draw-count rule (about 5 lines in checkSamples, exact, label-gated). 1 of 7 sample-set cards.
4. Build the mean/median/sigma reference-line rule, gated to one scatter series and excluding population/true/expected labels. It is the one definitional rule the Reviewer lists as unenforced; zero exposure in the current prompt set, so P2 insurance for stats lessons, not a measured fix.
5. Derive instead of check where the schema allows: turn on EXPLANATION_FORMULA_SAMPLER for plot y-values; add NO `balance` or `closing` field to t-account or waterfall (the renderer already derives them); do NOT enforce "every label number appears in the prose" (33% reject rate), and use the same-label-different-number rule as a report-only check instead.

Caveats: rates are from bench runs and cluster by prompt; the production archive is too small to measure. The softmax flags in `flags.csv` mix real errors with correct 1 dp roundings; per-item tolerance separates them. The prose-number and tree-count measurements in this file were computed fresh from `cards-all.json` (read-only); everything else is taken from the existing evidence files.
