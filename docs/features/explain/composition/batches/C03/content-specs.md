## ml-transformer-context-rules

GPT-2, BERT and Transformer-XL repeat different kinds of blocks for different ways of using context. Bidirectional and causal attention differ in which keys each query can read. Preserve a causal decoder, a bidirectional encoder and a decoder with prior-segment memory; use the same current sentence and focus position in all relevant views, with future positions hidden only on the causal sides. Overview can faithfully fit one categorical matrix: each architecture's current-segment permission and prior-segment-memory rule, with words such as “earlier + self”, “all positions”, and “cached earlier segment”; these are categories, not numeric measurements. Standard uses a pure two-panel comparison of same-sized heatmaps for causal versus bidirectional eligibility on `we read maps`, both marking the `read` focus and keeping token axes/order identical. Eligibility is a binary permission mask, explicitly not learned attention probabilities; blocked future cells are null, not a small positive weight. Deep keeps that comparison and adds a separate prior-segment heatmap whose columns are earlier memory followed by the same current words, with a clear segment boundary and no current-future access. The implicit invariant is that adding old-segment keys expands the visible past without making current-segment causality bidirectional. Repeating the block recipe is structural and does not imply shared parameters across different layers or interchangeable model families. Preserve both source summaries verbatim and empty lessons; do not fold this into a causal-mask-only reference that loses Transformer-XL.

Suggested keywords: `architecture context rules`, `prior segment context`. useWhen: “Compare causal, bidirectional and prior-segment context permissions on aligned token positions; not numerical score normalization, a decoder KV-cache implementation, or encoder–decoder cross-attention.” The existing concise causal-mask questions must retain their current picks.
