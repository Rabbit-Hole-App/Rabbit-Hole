## Evidence requirements

Every receipt records the exact commit, dirty files, runtime/image digest, cadgen version, skill revision, environment, invocation, elapsed time, and separate passed/failed/skipped/interrupted counts. A blocked check is not a pass. Record screenshots for pending, ready, failed and edit-preview states. Never record credentials, private prompts or filesystem paths in public operational logs.

## Initial infrastructure risks

- The conversion service already has Linux process/network/mount isolation and resource controls, but its fixed converters do not execute cadgen. Reuse the safety mechanisms; do not advertise that service as a CAD executor without proof.
- Its scratch tmpfs is bounded, while the bound host job directory and per-file size limit do not establish a total workspace disk bound for generated Python. CAD needs an aggregate job-storage limit and symlink-safe artifact extraction.
- File-source access grants a referenced source to authorized canvas viewers. Keep private generation references/context separate from the generated model's shareable source and artifacts.
- Paid transport currently creates a fresh operation identity per invocation. Durable CAD retries need persisted model-operation identity and ownership fencing before calling it; artifact deduplication alone does not prevent duplicate charges.
- Persisting a job and then failing to schedule it is not acceptance. Either prove a durable wakeup is scheduled before success or return a recoverable failure without claiming generation has started.

## Proposed real-model approval

No model calls may run until CAD-specific approval and access/billing verification. Prefer verified subscription-backed access. A configured API key is not spending authorization. Missing subscription routing must be reported, not silently bypassed.

Use four scenarios, with no extra benchmark campaign:

1. **Simple dimensioned part:** a 40 x 20 x 5 mm rectangular plate. Check one valid solid, exact named parameters, independently measured bounds and volume, STEP/GLB correspondence, thumbnail and saved card.
2. **Meaningful features:** a 60 x 40 x 5 mm plate, four diameter-4 mm through holes at explicitly supplied centers, and a centered 20 x 10 x 2 mm pocket. Check hole count/diameter/placement, pocket depth, exterior bounds and valid topology from trusted inspection.
3. **Invariant-preserving edit:** change only that pocket depth to 3 mm. Check exterior dimensions, hole pattern and card position/size/connections unchanged; preview before Accept; reload accepted revision; prior revision usable on failure.
4. **Clarification:** request a part that must mate with existing hardware while omitting its interface dimensions. The answer must ask for those dimensions, identify unresolved requirements and create no guessed geometry. Stop at the question; no follow-on generation in this scenario.

Expected provider requests: seven (three source-generation requests, three visual/requirements reviews, one clarification). Maximum eleven permits at most two additional repair-and-review pairs across the entire set. Transport retries count toward eleven; no hidden retry, provider fallback or automatic rerun. Unused repair allowance is not a reason to make extra requests.

Proposed model: `claude-sonnet-5-5`, subject to approved route availability. [Official model pricing](https://platform.claude.com/docs/en/models/sonnet-5-5/overview), checked 2026-10-17, is $2 per million input tokens and $10 per million output tokens. Cap each request at 20,000 total input tokens (including images/framing) and 6,000 output tokens (including thinking). Disable cache writes, separately billed provider tools and fast mode. This bounds a request to $0.10 and eleven requests to **$1.10**; seven at their maximum would be $0.70. These are upper-bound estimates, not measured cost or proof of billing. Enforce the shared conservative admission calculation before each request; refuse any request whose reservation exceeds $0.10 or whose aggregate reservations exceed $1.10. If a body cannot fit the input bound, reduce irrelevant context or report it blocked rather than increasing the allowance.

Approval should specify the route, maximum eleven requests and $1.10 total provider ceiling. Hosting/execution charges require their own infrastructure approval. Record actual provider usage, served model, ledger attribution and cost where available; unknown usage remains unknown. Existing pre-CAD model budgets do not apply.
