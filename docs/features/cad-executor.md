# CAD executor: implementation and proposed dev infrastructure

Status (2026-10-17): dedicated authorized dev executor deployed; deterministic Linux build, trusted inspection, GLB, thumbnail, STL and 3MF execution passed. The temporary dev executor was subsequently removed after integrated verification; saved artifacts remain available, but new builds need separately authorized infrastructure. No generated Python ran on the developer host. Real-model verification remains separate.

## Reuse and concrete gap

The released file-import infrastructure provides persisted D1 jobs, Durable Object alarms, leases, cancellation, attempt-scoped callbacks, R2 publication and authenticated artifact delivery. CAD orchestration reuses those patterns and existing storage/permission/accounting helpers. `packages/file-convert` remains unchanged. Its deployed image contains Office, FFmpeg and occt-import-js, not cadgen/native Python. Sharing that service would change its approved execution scope and compete with existing conversions.

The Windows workstation has Python 3.13 and uv, but no installed WSL or Docker and no cadgen/build123d/OCP. Cloudflare Workers cannot execute the native OpenCascade runtime. A new isolated executor is therefore proposed; provisioning was subsequently approved within the limits below.

## Executor contract

`POST /jobs` accepts `cad-execute/1` with `job_id`, `attempt`, `revision_id`, `operation` (`build`, `export`, `inspect`), source URL/bytes/SHA-256, requirements units/checks, formats, limits and callback URL/token/expiry. Build formats include `step`, `glb`, `thumbnail`. Service authentication uses `CAD_EXECUTOR_TOKEN`; callbacks use only their scoped attempt token, never provider credentials. `CAD_ALLOWED_ORIGINS` strictly bounds source and callback destinations; redirects are refused.

Callbacks below `/api/learn/cad/jobs/:id/attempts/:attempt` are progress, outputs, complete and fail. Progress stages are building/checking/exporting. Completion uses `cad-execute-result/1` with matching revision, hashed outputs, trusted validation, runtime and timings. Optional export failures are returned separately; missing required preview artifacts cannot constitute a ready result. Source already belongs to the control plane and is not uploaded twice. Export/inspect operate on saved STEP and cannot call a model. `GET /jobs/:id/:attempt` is advisory; `POST .../cancel` requests termination. D1 remains authoritative after process loss.

## Isolation and resource proposal

One separate dev Fly app, one shared-CPU-2x/4GiB machine, one CAD execution slot initially, no persistent volumes. Provisioned name: `rabbit-hole-cad-dev`, machine `8744117f0ed658` in iad. Reuse converter namespaces/cgroups with CAD-specific paths and limits. No network interfaces except private loopback for Chromium snapshots; no application secrets; read-only inputs/application files; dropped capabilities and supplementary groups; no-new-privileges. A fresh PID namespace and cgroup include descendant processes. Fail closed if kernel resource controls are unavailable. Job storage is a 512MiB tmpfs; private scratch is another bounded 512MiB tmpfs counted against the 2GiB child memory limit. Per-file artifacts cap at 50MiB, published aggregate at 100MiB, source at 4MiB, stage at 300 seconds and attempt at 600 seconds. Limits can be lowered per request, never raised above service caps.

Set `DO_NOT_TRACK=1`, `CADGEN_TELEMETRY=0`, `CADGEN_UPDATE_CHECK=0`, `CADGEN_DAEMON=0`, `CI=1` for each process. Detached shared upstream daemons/viewers are not launched; upstream deliberately strips some telemetry overrides when starting detached processes, so offline namespace enforcement remains essential. No upstream viewer is exposed publicly.

No proxy idle-stop while a job runs. The service exits after 300 idle seconds and auto-starts on dispatch; one machine only, no HA duplicate. Cancellation/shutdown terminates the active process namespace and callback publication is fenced by the control plane. Every phase removes its workspace; no private cache reuse across users. A process crash is detected through persisted leases and becomes an interrupted/recoverable job, not a claim of halfway-resumable geometry. Cleanup failure degrades admission. Full cleanup/security probes remain required on Linux before accepting generated source.
