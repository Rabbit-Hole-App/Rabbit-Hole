## What the classifications mean

The status applies to the **specific bounded teaching scene in that row**, not to every possible illustration or the complete curriculum topic. A 2D diagram explaining a training system is not the training system itself. A hypothetical model response is not a measured model result.

| Status | Meaning |
| --- | --- |
| S · Existing example | A directly relevant executable fixture already exists for the stated slice. It does not verify the entire topic, deployed behavior or fresh AI generation. |
| C · Compose | The named scene can plausibly be authored using inspected helpers and bounded JavaScript. No matching completed example is claimed; numerical logic, layout and generated-card acceptance still need implementation/verification. |
| G · Blocked scene | The exact proposed interaction needs missing support. The boundary gives a supported fallback where one exists. |
| X · Excluded scene | The specified interaction is outside the owner’s /interact scope; not backlog work. |

The final column separately identifies **richer variants that cannot currently be delivered**, even when a small scene is possible. Gap counts overlap: one topic can need both a model result and image binding. V is missing evidence/data, not a component build. D and X are recorded boundaries and are excluded from recommendations.

Shared bounds: 60 frame objects, four number/select inputs, eight selectable/drag targets and eight actions; 32 KiB saved state; 16 KiB program source. Grids are at most 6 × 6; cyclic helper is at most eight nodes/twelve edges; traces at most six lanes/twelve spans total. Numeric rasters are at most 64 × 64 each and 8192 pixels per frame. The sandbox has a 50 ms guest-operation deadline, a 16 MiB guest heap budget and a 32 MiB WASM cap. Small examples must share these limits rather than assume every helper can be used at its maximum simultaneously.

Pure programs can implement small algorithms from scratch. They cannot import PyTorch/JAX, call a provider, open a browser/terminal, fetch data, or access GPU services. Changing card controls currently reevaluates saved source locally. Source references in a card do not by themselves supply decoded pixels, model tensors or a live tool bridge.
