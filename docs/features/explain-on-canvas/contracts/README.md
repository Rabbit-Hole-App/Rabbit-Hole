## Gaps

Where v1.3/v1.4 conflict with the code on main or with cleanup-v0.4, or leave something open. The safer reading chosen is stated each time.

- **G1. `allowedPrimitives` premise.** v1.3 4.1/D2 says public `body.allowedPrimitives` cannot be trusted. On main nothing reads it: `artifactFetch` ignores it (`learn-artifact.js:160-161`) and `generateArtifact` has no such parameter (`:77`). The conclusion stands (the allowlist must be a server constant), but the mechanism is different: a trusted third-argument option (`adapter.md` 2). Chosen: never read it from `input`.
- **G2. The adapter needs two edits to an existing file.** The manifest says this lane edits no existing file, and v1.3 implies the restriction already exists. `generateArtifact` has no allowlist or system-suffix parameter, and `explain`'s `INTERACTIVE_WORDS` narrowing (`slash.js:39`) would make the intersection empty for a step titled "interactive ...". Chosen: describe the patch (`only`, `systemSuffix`, narrowing ignored when `only` is set) and list a weaker no-edit fallback; Lead decides (integration T3).
- **G3. Which model writes cards.** v1.3 6.1 lists only Sonnet 5.5 and Opus 5.5; the `artifact` task is `claude-opus-5` ($5/$25), provider `plan`, and goes to OpenAI if `OPENAI_API_KEY` and `LEARN_PLAN_MODEL` are both set (`learn-models.js:14,113`; `ask.js:271`). Chosen: cost estimate uses Opus 5 as the conservative bound; recommend a pinned `roadmap_card` task.
- **G4. "unused `attemptId` argument".** v1.3 5.1 warns about it; `spendTransport` has no such argument. The attempt id is the ledger `opId`, generated inside (`learn-spend.js:78`), and `anthropic()` passes only `{ provider }` (`ask.js:311`). Chosen: an env-Symbol carrier (`withOperationId`) like the existing `withAttemptKind`; plus replay handling, because a duplicate `op_id` is currently reported as an unrelated refusal (`learn-spend-ledger.js:78-80,94-96`).
- **G5. Step hold is not supported by current code.** v1.3 5.2 requires atomic aggregate admission and a transfer into per-call admission. `explain-job.js:11-14` documents the shortcut ("a check, not a hold"). Chosen: specify `admitStepHold` / `parentHold` (`billing.md` 4) and name the fallback and what it gives up. Step deadline must stay below `HOLD_SECONDS.artifact` = 3600 s.
- **G6. Card field names.** v1.3 names `step_id` and `source_ref`; card JSON in this repo is camelCase (`attemptId`, `confirmedStart`, `animation3dJob`). Chosen: `stepId`/`sourceRef` on cards, snake_case in D1 columns; R3 owns `sourceRef`'s shape.
- **G7. "Proposal" already means something.** `generation-proposal.js`, `meta.proposal`, `proposal_id` and `GenerationProposalCard` (`ChatMessages.jsx:16,208`) are the signed paid-generation proposals. Roadmap proposals are different records. Chosen: separate routes (`/roadmap/proposals`), table `roadmap_proposals`, no reuse of `meta.proposal`.
- **G8. Safety transport.** Confirmed: the webpage screen is one exclusive choice (`safe|explicit|graphic`) under policy `webcard-mod-p1` with its own thresholds; reusing its labels would be wrong. `askJev` admits each POST itself (`learn-grade-jev.js:150`), outside `spendTransport`, so the operation-ID hook must be applied there too (`billing.md` 8.13).
- **G9. Billing outcome has no "unknown".** v1.3 4.3 lists pending, settled, refunded, failed, zero-priced, yet 5.1 requires reconciling unknown outcomes. Chosen: a separate `RECONCILIATION` dimension (`none|required|complete`), leaving the 4.3 list verbatim.
- **G10. Cleanup v0.4 vs main.** `spendCallModel` still lives in `learn-tutor-routes.js:43` (P1 moves it to `learn-spend.js`); the `tutor`, `tutor_evaluator` and `journey_*` tasks are still in `learn-models.js`, and are removed in P3/P4. R4 uses none of them and calls `spendTransport` directly, so it does not depend on P1's move. R4 depends on cleanup only as `integration.md` section 2 lists, each to be verified at integration; no removal is assumed. Hot files overlap (`learn-usage.js`, `learn-models.js`, `LearnPage.jsx`, `dev-worker.js`): small hunks only.
- **G11. `*.draft.sql` is `broad`.** `scripts/ci/check-map.json` has `**/*.sql` in `broad`, checked before `docs`. Pushing `roadmap-r4.draft.sql.txt` selects every Linux check (96 in a scratch run). The instructed filename was kept; fix is `git mv roadmap-r4.draft.sql.txt roadmap-r4.draft.sql.txt` before the first push (classifies `docs`). `states.js` needs its mapped row (`integration.md` 8).
- **G12. DO granularity.** v1.3: one `RoadmapJobs` per learner and board. The precedent `ExplainJobs` is one per board (`idFromName(board.id)`). Chosen: name from `org:ownerUserId:boardId`; equal to per-board until R14.
- **G13. Transitions the roadmap leaves open.** `cancelled -> proposed` only by an explicit learner action; `completed -> active` only with an accepted revision; a stale `pending` proposal returns to `checking`; `failed` roadmap may return to `draft`. Recorded in `states.md`.
- **G14. Docs the roadmap says to keep do not exist.** v1.3 11.3: `docs/features/explain-on-canvas/STATUS.md`, `checklist.md`, `parked.md`, receipts. The directory did not exist on main; this lane creates it with `contracts/` only. Lead owns receipts.
- **G15. Plain Tab has no owner in `shortcut-owner.js`.** It models Ctrl/Cmd chords (`CHORDS`) and a plain/Shift guard (`pageKeyAllowed`); Tab acceptance must be written in the canvas key handler beside `busy`/`plain` (`AdaptiveCanvas.jsx:3735-3739`). `ui.md` 3 gives the predicate.
- **G16. Source reading.** v1.3 says "within a declared processing bound" without a number or a reader. The existing `fileContext` caps (4000/12000 characters) silently cut text, so it cannot serve whole-source planning. Chosen: a dedicated reader over `file_derivatives` and an explicit proposed bound of 40,000 characters (decision T2); per-step passage <= 8000 characters because the adapter's context cap is that large.
- **G17. Retention and cron.** D16's daily cron is R11's; R4 prunes lazily. A memory note says Cloudflare cron ticks were not delivered (2026-09): unverified now, irrelevant to R4.
- **G18. Owner records.** v1.4 9.2 lists items that are owner-only. The MVP label is recorded in the manifest; the rest are proposed in `decision-records.md` and not assumed.
