# Adaptive Learning Canvas — Product & Engineering Spec

## 0. Purpose

This document defines the new adaptive learning experience for the course-generation product.

The product should no longer behave like a sequence of slides or a passive lesson player. The main surface should become a **persistent, vertically growing learning canvas** that evolves as the learner progresses.

> **AI builds a learning workspace with the learner until they understand the subject.**

The canvas should accumulate explanations, diagrams, code, interactions, learner answers, questions, corrections, and follow-up teaching branches. The right-side AI tutor remains present, but it becomes context-aware and acts on the current learning object rather than behaving like a generic chatbot.

---

## 1. Product direction

### Current product

The current UI has:

- a large main tldraw canvas
- a chat/tutor panel on the right
- lesson navigation/progress controls
- generated diagrams and explanations on the main canvas

This is a strong starting point, but the main area should evolve from a slide-like canvas into an **adaptive learning document/workspace**.

### New direction

The main learning area should:

- scroll vertically
- accumulate as the learner progresses
- preserve earlier explanations above
- append new teaching blocks below
- adapt based on learner answers, questions, selections, slider/graph interactions, quiz performance, prior mistakes, and mastered concepts
- allow the learner to return to previous concepts
- keep a visible record of the learner's journey

```text
Lesson starts
    ↓
Challenge
    ↓
Visual explanation
    ↓
Interaction
    ↓
Learner answer
    ↓
Adaptive decision
    ├── understood → continue
    └── confused → append remediation
                        ↓
                    retry/check
                        ↓
                    continue
```

## 2. Critical architecture decision

### React is the main learning canvas

Do **not** make the entire adaptive learning experience one giant unconstrained tldraw board.

Use:

```text
Next.js / React
│
├── AdaptiveLearningCanvas
│    │
│    ├── ChallengeBlock
│    ├── ExplanationBlock
│    ├── DiagramBlock
│    ├── CodeBlock
│    ├── InteractivePlotBlock
│    ├── InteractiveControlBlock
│    ├── KnowledgeGraphBlock
│    ├── ThreeDBlock
│    ├── VideoBlock
│    ├── QuizBlock
│    ├── FlashcardBlock
│    ├── RepoReferenceBlock
│    ├── NotebookBlock
│    ├── RemediationBlock
│    └── WhiteboardBlock  ← tldraw
│
└── ContextualTutorPanel
```

React owns:

- vertical flow
- block ordering
- responsive layout
- adaptive insertion/removal
- lesson progress
- block-level state

This avoids manually solving all x/y positioning, vertical collisions, dynamic insertion, responsive reflow, content overflow, and long-page scrolling.

### tldraw remains important

tldraw becomes a **specialized learning primitive**, not the entire page.

Use it for:

- drawing
- circling
- freeform annotation
- handwritten notes
- arrows
- open-ended diagrams
- spatial reasoning
- whiteboard-style explanations

## 3. Core learning model

Do not think in pages:

```text
Page 1 → Page 2 → Page 3
```

Think in learning blocks/scenes:

```text
Lesson
 ├── Scene / Block 1
 ├── Scene / Block 2
 ├── Interaction
 ├── Adaptive branch
 ├── Scene / Block 3
 ├── Check
 └── Recap
```

A lesson should feel like a guided path through a living learning workspace.

## 4. Three kinds of state

### 4.1 Teacher state

Generated by the course:

- explanations
- diagrams
- equations
- code snippets
- images
- graphs
- architecture maps
- videos
- 3D visualizations
- questions
- worked examples
- challenges
- source references

### 4.2 Learner state

Created by the learner:

- handwritten notes
- circles/highlights
- answers
- sketches
- selected objects
- slider changes
- graph interactions
- code edits
- questions asked
- notebook experiments

### 4.3 Learning state

Maintained by the system:

- concepts seen
- concepts mastered
- concepts still weak
- confidence estimates
- failed checks
- misconceptions
- remediation history
- current learning objective
- next recommended concept

Example:

```ts
type ConceptState = {
  conceptId: string
  status: "unseen" | "learning" | "mastered"
  confidence: number
  attempts: number
  lastSeenAt?: string
  misconceptions?: string[]
}
```

## 5. Canvas accumulation model

Prefer an **append-only teaching history**.

If the learner asks a question or gets something wrong, do not replace the whole lesson.

```text
Original explanation
    ↓
Learner question
    ↓
Adaptive explanation
    ↓
Understanding check
    ↓
Continue
```

The canvas becomes a record of what was taught, what confused the learner, how it was resolved, and what the learner successfully understood.

---

## 6. Core adaptive loop

This should be one of the defining product features.

```text
User selects / circles something
        ↓
System resolves semantic target
        ↓
User asks a question
        ↓
Tutor receives current context
        ↓
Tutor chooses remediation type
        ↓
New learning block appears below
        ↓
Learner completes micro-check
        ↓
Mastery state updates
        ↓
Continue or remediate again
```

Do not ask only:

> Do you understand?

Require evidence instead:

- explain it in one sentence
- choose between 3 possibilities
- predict what happens next
- manipulate a slider
- identify the affected code
- solve a tiny transfer problem
- fix an incorrect statement

## 7. Selection / circle → contextual teaching

Every meaningful object should carry semantic metadata.

```ts
type SemanticObject = {
  objectId: string
  conceptId?: string
  blockId: string
  type:
    | "concept"
    | "equation"
    | "code"
    | "diagram_node"
    | "graph"
    | "graph_point"
    | "image_region"
    | "architecture_component"
  label?: string
  sourceRef?: {
    repo?: string
    path?: string
    symbol?: string
    lines?: [number, number]
  }
}
```

Example: the learner circles `Embeddings` and asks:

> Why do we need this?

The agent should receive something like:

```json
{
  "question": "Why do we need this?",
  "selectedObjects": [
    {
      "id": "token-embedding",
      "type": "architecture_component",
      "concept": "token embeddings"
    }
  ],
  "lesson": "Inside nanoGPT",
  "learnerState": {
    "tokenization": "mastered",
    "embeddings": "learning"
  }
}
```

Then append a targeted explanation below the current block.

## 8. Example adaptive branch

Current lesson:

```text
Token IDs
   ↓
Embeddings
   ↓
Transformer Blocks
   ↓
Logits
```

Learner circles **Embeddings** and asks:

> Why can't we feed token IDs directly?

Append:

```text
Your question:
"Why can't we feed token IDs directly?"

Let's use a smaller example.

Token ID: 42

42
 ↓
Embedding lookup
 ↓
[0.17, -0.81, 0.42, ...]

The ID is only an index.
The embedding is the learned representation.

Check your understanding:

If the token ID changes from 42 → 43,
what changes first?

A. The selected embedding row
B. The vocabulary size
C. The number of transformer blocks
```

Correct:

```text
✓ Good — continue
```

Incorrect:

```text
Let's look at this another way
↓
append simpler diagram
↓
new check
```

## 9. Recommended lesson loop

The AI-native learning loop is:

```text
Challenge
→ Intuition
→ Visual explanation
→ Manipulate / interact
→ Connect to repo
→ Explain back
→ Transfer challenge
→ Spaced recall later
```

Avoid a default of:

```text
long explanation → quiz → next lesson
```

## 10. Further explanations and deeper content

Use three content layers.

### Layer 1 — Core guided lesson

Always visible. Short, focused, interactive.

### Layer 2 — Further explanation

Generated with the course, but hidden by default.

Every important concept can expose:

```text
[Explain more]
```

Example:

```text
Token Embeddings       [Explain more]
Position Embeddings    [Explain more]
Transformer Blocks     [Explain more]
LM Head                [Explain more]
```

Further explanations may include:

- worked example
- code reference
- equation
- additional diagram
- misconception
- analogy
- source/reference
- optional deeper reading

### Layer 3 — Custom tutor response

Generated on demand from the learner's actual question, selection, and learning state.

---

## 11. Video policy

Video is optional, not mandatory.

Use generated video for:

- physical processes
- robotics
- real-world motion
- 3D spatial intuition
- scientific mechanisms
- dynamic scenarios
- transformations over time

Do not use generated video for:

- exact equations
- code
- exact architecture diagrams
- tensor shapes
- precise algorithms
- ordinary plots

Support:

```ts
type MediaImportance = "core" | "optional"
```

If `core`, generate/cache during course creation.

If `optional`, show a `Watch visualization` affordance and generate/load only when requested.

## 13. Agent contract: semantics, never UI code

The lesson agent must **not** generate arbitrary:

- React
- JSX
- JavaScript
- tldraw coordinates
- Three.js code
- Plotly code
- Desmos code

It emits validated semantic specifications.

Example:

```json
{
  "action": "append_block",
  "block": {
    "type": "worked_example",
    "conceptIds": ["token-embeddings"],
    "purpose": "remediation",
    "title": "An ID is not a representation",
    "content": {
      "exampleTokenId": 42
    }
  }
}
```

The frontend chooses the renderer.

## 14. Interactive controls

Build a generic primitive.

Do not create `GPTLayerSlider`.

Create `InteractiveControlBlock`.

Supported controls:

- slider
- toggle
- dropdown
- button
- stepper

Example:

```json
{
  "type": "interactive_control",
  "id": "layer-control",
  "control": "slider",
  "parameter": "n_layer",
  "label": "Transformer layers",
  "min": 1,
  "max": 12,
  "step": 1,
  "value": 4,
  "target": "gpt-architecture"
}
```

When `n_layer` changes from `4 → 8`, the target visual updates.

The control should not know how the target renders.

## 18. Example — nanoGPT Lesson 2

### Lesson

**Inside nanoGPT: How token IDs become predictions**

Goal:

```text
token IDs
→ embeddings
→ transformer blocks
→ normalization
→ LM head
→ logits
```

### Block 1 — Challenge

Ask:

> We know nanoGPT receives token IDs. What has to happen between these integers and next-token predictions?

Learner commits before explanation.

### Block 2 — Architecture reveal

Progressively reveal:

```text
Token IDs
   ↓
Token Embeddings
   +
Position Embeddings
   ↓
Transformer Block × N
   ↓
LayerNorm
   ↓
LM Head
   ↓
Logits
```

Do not explain Q/K/V yet.

### Block 3 — Interaction

```text
Layers        [────●────]
Embedding dim [──●──────]
Heads         [───●─────]
```

Changing `n_layer` updates the architecture visual.

### Block 4 — Repo connection

Map:

```text
wte     → token embeddings
wpe     → position embeddings
h       → transformer blocks
ln_f    → final normalization
lm_head → vocabulary scores
```

Clicking code highlights architecture.
Clicking architecture highlights code.

### Block 5 — Tensor challenge

Given:

```text
batch = 4
sequence = 8
embedding dim = 64
```

Ask:

> What is the embedding tensor shape?

Expected:

```text
[4, 8, 64]
```

### Block 6 — Explain-back

Ask:

> Explain what happens between token ID 2 entering nanoGPT and the model producing next-token scores.

Tutor evaluates the explanation.

### Block 7 — Transfer

Ask what changes when:

```text
n_layer = 6 → 12
n_embd = 384 → 768
vocab_size = 65 → 50000
```

### Block 8 — Recap

Learner reconstructs:

```text
Token IDs
  ↓
[ ? ]
  +
[ ? ]
  ↓
[ ? ] × N
  ↓
LayerNorm
  ↓
[ ? ]
  ↓
Logits
```

## 19. Right-side tutor behavior

Keep the tutor panel on the right, but make it contextual.

Example context:

```text
Current lesson:
Inside nanoGPT

Current block:
Transformer architecture

Selected object:
Token embedding

Learner action:
n_embd changed 128 → 512

Known misconception:
Confused embedding width with vocabulary size
```

Suggested questions:

- Why does increasing `n_embd` increase parameters?
- Where is this defined in `model.py`?
- Does a larger embedding dimension mean a larger vocabulary?
- Show me a simpler example.

The tutor should often respond by **adding a block to the learning canvas**, not only by adding a chat bubble.

## 20. Learning event log

Maintain a durable event log.

```ts
type LearningEvent =
  | { type: "block_viewed"; blockId: string }
  | { type: "question_answered"; blockId: string; correct: boolean }
  | { type: "slider_changed"; targetId: string; parameter: string; from: number; to: number }
  | { type: "object_selected"; objectId: string }
  | { type: "user_question"; objectId?: string; text: string }
  | { type: "remediation_inserted"; blockId: string }
  | { type: "concept_mastered"; conceptId: string }
  | { type: "concept_confidence_updated"; conceptId: string; value: number }
```

This is one of the main inputs to the adaptive engine.

## 21. Adaptive engine

The adaptive engine answers:

> What is the next best learning block?

Inputs:

- current lesson goal
- current concept state
- current block
- recent answers
- learner questions
- interaction events
- repo context
- time budget

Possible outputs:

- continue
- insert worked example
- insert simpler explanation
- insert interactive visual
- insert code connection
- insert analogy
- insert transfer problem
- insert recap
- skip concept

## 23. Vertical layout rules

The React learning canvas owns the vertical flow.

Each block should:

- have intrinsic height
- expand naturally
- maintain consistent spacing
- push later blocks down automatically
- avoid manual y positioning across blocks

The LLM must not position blocks.

Within specialized blocks, the local renderer may manage its own internal layout.

Examples:

```text
React Flow + ELK → graph layout
Plotly           → graph layout
tldraw           → whiteboard geometry
Three.js         → 3D layout
```

## 24. Template system inside blocks

Useful templates:

- `compare_processes`
- `explain_visual`
- `step_through_process`
- `concept_to_code`
- `explore_and_check`

The LLM chooses the template and supplies content.

The renderer owns spacing, measurements, coordinates, overflow, and consistency.

Example:

```json
{
  "template": "compare_processes",
  "title": "Training vs Generation",
  "left": {
    "label": "Training",
    "steps": [
      "Known text",
      "Predict",
      "Compare",
      "Update parameters"
    ]
  },
  "right": {
    "label": "Generation",
    "steps": [
      "Prompt",
      "Predict",
      "Select token",
      "Append token"
    ]
  }
}
```

## 25. Overlap / layout safety

Do not solve overlap using prompting alone.

The renderer must:

- measure text before placement
- wait for fonts before measurement
- reserve final text space before character-by-character animation
- enforce max content per local template
- return overflow errors
- split content when necessary
- check collisions inside local diagrams
- prevent clipped content

For long content:

```text
shorten
or
split into a new block
```

Do not continuously shrink font size.

## 31. MVP acceptance criteria

The first adaptive-canvas milestone is complete when:

1. A lesson renders as vertically stacked React learning blocks.
2. New blocks can be appended without manual repositioning.
3. Earlier blocks stay visible above.
4. The right-side tutor knows the active block.
5. A learner can select/circle a semantic object.
6. A question can be asked about that object.
7. The tutor appends a targeted remediation block below.
8. The learner receives a micro-check.
9. Correct/incorrect answers update concept state.
10. A wrong answer can trigger a second remediation block.
11. The lesson can continue after the branch.
12. The event log records what happened.
13. Reloading restores the lesson and adaptive branches.
14. The LLM does not generate JSX, pixel coordinates, or arbitrary code.

## 33. Guiding product principle

The product is not:

> AI generates courses.

The product is:

> **AI builds an adaptive learning workspace with you, grounded in the source material, until you can demonstrate understanding.**

The canvas is not a presentation.

It is the learner's **living knowledge workspace**.
