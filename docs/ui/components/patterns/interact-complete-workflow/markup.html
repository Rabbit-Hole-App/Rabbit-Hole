/interact — Complete Workflow

Design the scene → review the completed plan in Chat → build the scene → compose the card → deliver it.

The final Story, updated scene design, Mode and Controls must exist before Chat review. Generate approves that plan and starts building the runnable scene. This documents the agreed target workflow, not a claim that the pipeline is already implemented.

1. Scene design, approval and build

Independent review checks factual correctness, depth fit, teaching clarity, scene competence, and agreement between Story, Scene, Mode and Controls. Revision updates the complete specification. User edits return through design review before approval.

The shared scene specification

This is the complete handoff shown in Chat. “Updated scene” here means the reviewed scene design. The executable scene is built after Generate.

TitleWhat this card explains.
Story / descriptionThe learner-facing narrative from question through discovery to answer, appropriate to the selected depth.
Supporting static visualsOptional comparisons, diagrams or snapshots that help explain the scene.
Updated scene designWhat appears, what happens, what changes and what the learner should observe.
ModeStatic, Over time or Experiment; initial state, time behavior, and fixed or adjustable inputs.
ControlsEvery required control, including labels, behavior, defaults, ranges, units, steps and bindings where applicable. Explicitly empty when no controls are needed.

2. Card composition

  • Explanations and supporting static visuals go above the main scene.
  • The animation sits immediately next to playback and its timeline, with no static explanation between them.
  • Playback and experiment controls stay outside the scene.
  • Static scenes have no timeline and fit their content without unused bottom space.
  • Overview, Standard and Deep are independent of Mode. Depth does not automatically select a presentation.

Implementation and benchmarking

Recommended implementation: Claude Code builds one shared runner in the Rabbit Hole repository, used by both the script and /interact. Three design roles — Author, Reviewer and Reviser — precede scene building and validation. Opus can initially serve every LLM role. The existing UI renderer enforces card composition; composition does not need another LLM role.

Generate the selected depth for ordinary /interact requests. Benchmark all three depths and record Send → reviewed plan ready, Generate → usable card ready, and factual and behavioral correctness separately. Repairs add to measured latency. A three-role design stage is not a guarantee of three total calls for the complete pipeline.
