# Benchmark Mode

## Purpose

Benchmark mode answers:

> Can our generic visualization runtime teach the same concept with comparable clarity and capability?

It does **not** answer:

> Can we reproduce the reference artwork pixel-for-pixel?

The external reference is used as a teaching-quality benchmark, not as a production design template.

## What to match

Optimize for **semantic / pedagogical parity**:

- the same core concepts are represented;
- the same important relationships are visually understandable;
- the information hierarchy is comparably clear;
- progressive disclosure is comparably effective;
- the learner can follow the same reasoning path;
- interaction capability is comparable when the benchmark is interactive;
- the generated scene remains readable at all benchmark keyframes;
- no important relationship requires explanatory prose because the diagram failed to carry it.

## What is NOT scored

Do not reward similarity in:

- exact colors or palette;
- exact block shapes;
- exact arrowhead or line style;
- exact typography;
- exact wording or captions;
- exact coordinates;
- exact spacing values;
- exact illustration details;
- exact animation timings;
- decorative artwork.

These should come from the Learn visual language.

## Hard rule

**Do not optimize toward a visual clone.**

A benchmark may reach 5/5 even when it looks visibly different from the reference if it communicates the same technical relationships with comparable or better clarity.

## Allowed reference use

The visual critic may see reference images.

The visual-director agent may see:
- the benchmark objective;
- reference notes;
- extracted teaching pattern;
- optionally reference screenshots during benchmark development.

Any reusable lesson-generation / production path must not depend on the external screenshots.

## Failure repair rule

If a benchmark reveals a weakness, repair the reusable system:

- primitive;
- template;
- layout algorithm;
- edge routing;
- typography;
- semantic role system;
- motion grammar;
- coordinated-view mechanism.

Never repair a benchmark by adding reference-specific styling or custom scene code.
